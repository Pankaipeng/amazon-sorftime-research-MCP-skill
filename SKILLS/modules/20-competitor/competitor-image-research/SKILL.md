# 竞品图片卖点拆解

## 采集

1. 读取用户指定站点、ASIN 和分组。支持 `00-input` 的 `groups` 契约或明确指定的 ASIN 列表。保留分组和输入顺序，同站同 ASIN 只采一次。用户给的竞品组与自动扩池分别统计，按用户指定范围采集。
2. 逐个调用卖家精灵 MCP `keepa_info`，请求 `marketplace,asin,dataAsin,brand,title,imageUrl,imageUrls`。`imageUrls` 是有序图集，数量随 ASIN 变化。用 `imageUrl` 的图片 ID 核对首图。若字段缺失，查一次完整响应，记录失败或缺图。若站点或实际数据 ASIN 不匹配，保留异常记录，禁止套用到该商品。
3. 将结果写入 `keepa-source.json`，结构为 `{"marketplace":"US","captured_at":"YYYY-MM-DD","groups":{"head":["B087G4JMF9"]},"results":{"B087G4JMF9": {...}}}`。`results` 按请求 ASIN 保存接口的 `data`，失败时写 `null`。运行 `python SKILLS/scripts/collect_competitor_images.py --source <keepa-source.json> --out <分析目录>/image_pack`，需要 Pillow 和 curl。脚本优先尝试亚马逊 CDN 的 600 版，再回退到接口返回链接。以 `manifest.csv` 为索引，保留原位次、采集日期、原链接、实际下载 URL 和状态。每次采集使用独立输出目录。
4. 报告成功图数、接口返回图数、成功 ASIN 数和请求 ASIN 数。下载失败保留原位次。页面图集存在无法确认的首图时标记 `首图待核`，仅在主图身份可核实时纳入主图结论。

## 逐图阅读

直接查看图像。图多时先做每个 ASIN 的编号联系表，模糊的小字回看单图。逐图生成 `逐图拆解.csv`，每张可判读图至少一行，多个独立卖点可各占一行。原位次始终按图集顺序。按实际内容填 `展示任务`，允许一图多任务。

### 主图：点击率（CTR）目标

按搜索结果缩略图的观看条件分析。记录第一眼看到的商品或用途、形成点击焦点的画面手法，以及手法可能提高点击意愿的原因。手法看商品视角、主体清晰度、背景对比、用途提示、配件或道具的位置，以及与组内其他首图的可辨识差异。输出「点击焦点 → 画面手法 → 点击假设」，保留对应原图。

### 副图：购买转化率目标

按「买家问题 → 卖点 → 画面证据 → 预期降低的购买顾虑」拆解，标主任务和辅助卖点。结构特写、动作演示、场景及对照按它们实际能说明的内容记录，文字声称单独标出。汇总卖点首次出现在第几张副图，并记录前后图如何协同讲清同一卖点。

常规尺寸标注图和包装清单图属于基础信息。保留原图位和用途，排除这些内容的卖点映射、覆盖统计和排序。一张图同时包含基础信息与独立卖点时，只拆该卖点。例如仅标三围是基础信息；用有依据的对比清楚展示窄槽也能安装，拆「窄槽适配」。

CTR 和购买转化率是分析目标。缺少可归因的同口径数据或实验时，将画面机制写为假设，实际效果标记未验证。

| 必填字段 | 记录内容 |
| --- | --- |
| `marketplace,asin,pos,file` | 能在 `image_pack/manifest.csv` 查回同一张图 |
| `展示任务` | 主图标点击策略。副图标卖点转化或基础信息 |
| `数据目标,展示机制,效果状态` | 主图记点击焦点和点击假设；卖点副图记画面如何降低购买顾虑；基础信息记用途。无可归因数据或实验时效果标未验证 |
| `画面事实` | 只写图中可指认的主体、动作、标注、构图或可读文字，模糊部分标待核 |
| `竞品声称` | 明示的判断、数字或效果。无明确声称留空，推断写进买家问题并注明依据 |
| `买家问题,主题` | 用中性词归并同义表达，记录它想回答的购买疑虑 |
| `视觉证据` | 结构特写、场景演示、尺寸线、步骤、对照或纯文字等，说明图能支持到什么程度 |
| `本品核验` | 使用同类表达前应核对的本品事实、照片或实测。仅有营销宣称时写清缺什么 |

## 汇总和交接

- 在 `竞品图片卖点与展示逻辑.md` 写清站点、日期、样本分组、覆盖和异常。逐 ASIN 归纳主图点击手法与副图卖点顺序，保留图集原位次。副图前段指标注明副图范围，如附图 1–3，同时保留对应的图集位次。
- 副图同主题按 ASIN 去重。同一 ASIN 的重复图不增加计数，跨 ASIN 复用图另外标注。给每个频次附已判读的副图 ASIN 分母和代表 `ASIN#图位`。按买家决策影响和可展示证据解释优先级。
- 将能明确对应的副图卖点映射至 `40-selling-point` 的 `SP ID`，保留源图及本品核验项。主图点击策略随报告提供，使用单独的点击观察口径。本品尺寸、配件、材质和性能由本品事实或实测支持。由 40 审阅并确定图片卖点排序。
- 交付前核对清单与逐图行的 `marketplace + asin + pos + file` 一一可追溯，对照原图抽查数字、文字与主副图身份，重新计算汇总分母。

## 接入卖点库

复核副图表中的 `SP_ID` 后，准备排序依据 JSON 数组。每项包含按主卖点、支撑卖点排列的 `sp_ids`，以及 `task`、`why`、按 SP ID 写明验收动作的 `checks`。排序按图片购买任务与本品证据决定。仅结构素材和性能声称保留各自边界。

```bash
python SKILLS/scripts/merge_image_selling_evidence.py --base <40现有产物目录> --secondary <副图拆解CSV> --manifest <image_pack/manifest.csv> --plan <排序依据JSON> --out <独立输出目录>
```

复核三路汇总、扩展证据链、图片卖点排序、FAB 卡和自检清单。图片覆盖以已判读 ASIN 计，五点和评论沿用原样本及统计口径。排序状态由需求负责人确认，图稿验收状态由实际复核填写。

方法参考 [史莱姆的竞品图片分析](https://github.com/knight9629/slime-amazon-design-skill/blob/main/skills/amazon-competitor-creative-research/SKILL.md) 的逐图阅读、跨竞品归并、展示顺序归纳和本品核验思路。
