# 10-keyword 实测问题清单

## 2026-11-13 · Nieifi 吸盘海绵架（US，9 个竞品 ASIN）

### 工具层面

| 工具 | 文档怎么说 | 实际怎样 | 影响 | 处理 |
|---|---|---|---|---|
| `asin_detail` | 返回 title / bullets / description | **`bullets` 和 `description` 都是 null** | 方法 C（Listing 词频）跑不了 | 方法 C 标 `DATA_MISSING`，只跑方法 B |
| `product_research` | 支持 `asins` 数组筛选 | **参数被忽略**，返回全站热销（能量饮料） | 不能按 ASIN 批量取数 | 不要依赖；用 `asin_detail` 逐个取 |
| `competitor_lookup` | 支持 `page` / `size` | **两者都被忽略**，永远返回第 1 页 5 条，但 `total` 真实（37） | 扩池只能拿 5 条 | 扩池主力改用 `asin_competitor` + 类目 `product_research` |
| `traffic_keyword` | 单个 ASIN 词量正常 | 实测 1,017–1,724 条（`total`），单次最多回 50 | 大 ASIN 要翻页 | 先看 `total`，超过 50 就翻页 |
| `traffic_keyword` | `conversionKeywordType` 多数为 null | 本次实测**有值**：`stable` / `excellent` | 之前写的「基本拿不到」过于绝对 | 有值就用，为空才标 `DATA_MISSING` |
| `keyword_order` | 取竞品出单词 | 依旧全空（`total: 0`） | 转化分层拿不到 | 已改走 `traffic_keyword` 的 `conversionKeywordType` |

### 方法层面

| 问题 | 具体表现 | 处理 |
|---|---|---|
| 层级判定规则有 bug | 「词数 ≥ 4 → 长尾词」把 `sponge holder for kitchen sink`（167,620 搜索、5 个词）判成长尾 | 改为「词数 ≥ 4 **且** 搜索量 < P75」 |
| 大词门槛过高 | P90 门槛下 `kitchen sink accessories`（71,536 搜索）落成核心词 | 大词门槛改 P75 |
| 自动补全请求数算错 | 文档写 1+3+26=29，实际 30 | 已更正为 30 |
| 颜色词淹没补全结果 | 26 个字母后缀里，b/c/p/m 四个字母几乎全是颜色词（black / bronze / brass / chrome / pink / marble），对本类目无用 | 用 `--mode fast` 的 10 个字母即可，颜色类词频较高的类目可再删 b、p |
| 品牌词占标题词频前列 | `sunnypoint` / `neverrust` / `toplife` / `taili` 进了 Top 10 | `freq.py` 需要 `--strip-words` 或统计前手工剔除品牌 |
| 竞品标题高度同质 | 9 个竞品里 7 个写 suction cup、4 个写 adhesive mount | 说明吸盘已是入场券，不是差异化——判断差异化要看 `coverage`，不看绝对词频 |

### 流程层面

| 问题 | 说明 | 处理 |
|---|---|---|
| 方法 C 缺数据时不要硬凑 | 没有 bullets 时，用标题词频假装成 Listing 词频会产生误导 | 必须在报告里写明「方法 C 未执行」 |

## 2026-11-13 追加 · 补池漏掉类目第一

**问题**：第一轮只靠 `asin_competitor` + 用户给的 6 个 ASIN 扩池，漏掉了整个类目的第一名 Cisily（B0C3QZ7SNF，月销 53,444、15,602 条评分、Kitchen Storage Accessories 类目第 1、30 个变体）。

**后果**：
- 上游 ABA 报表里 Cisily 是绝大多数词的「点击量第 1 品牌」，池子里却没有它
- 「刷子位」被我判成差异化卖点（以为只有 TAILI 的 4-in-1 有），实际 Cisily 主打的就是 `Sink Organizer with Brush Holder`——它是入场券，不是差异化
- 整份 v1 报告的差异化结论因此是错的

**根因**：`asin_competitor` 只按「相似商品」扩，不带销量权重，也不保证覆盖头部。只按 ASIN 反查会造成样本偏斜。

**修正（已写进 SKILL.md 已知限制）**：
扩池必须两步——
1. `asin_competitor` 从用户 ASIN 扩一层
2. **按类目 `nodeIdPath` + `nodeIdPathEqual: true` 拉 `product_research`，按 `total_units` 降序取 Top 10**，逐个核对是否已在池里

第 2 步才是保证「类目头部不缺席」的那一步，不能省。

**校验方法**：拿用户上传的 ABA 报表里的「点击量第 1 品牌」列，和池子里的品牌对一遍。有对不上的，说明漏了人。

## 2026-11-13 追加 · 方法 C 的替代口径

真 Listing 文本拿不到时，可以用 ABA 报表里的商品标题做代理：把标题按 `|` 拆开，取第一段之后的卖点堆叠部分做词频。

**必须标清楚**：这是「标题后半段的卖点表达」，不是完整五点。报告里要写「方法 C：代理数据」，不能写成「方法 C 已完成」。

**实测效果**：16 个去重标题里只有 7 个含 `|`，得到 23 个词组，覆盖率足够看出来 `rustproof 304 stainless steel` / `brush holder` / `drain` 是通用表达，但拿不到完整五点里的话术结构。
