# 方法 A：竞品 ASIN 反查

> 导图子项：竞品 asin 反查出单词 + 反查竞品 asin 库（增加样本数据）

两件事：**先扩池，再从池子里榨词**。顺序不能反——池子不够大就榨词，得到的只是几个头部竞品的词，那叫抄作业，不叫调研。

---

## A1. 扩池（反查竞品 asin 库）

### 输入

`00-input/竞品asin组.json` 里的 head / direct / new 三类。

### 步骤

```python
# 第一跳：从用户给的每个 ASIN 往外扩
pairs = []
for asin in head:   lvl = 0     # 权重 3
for asin in direct: lvl = 1     # 权重 1
for asin in new:    lvl = 1.5   # 权重 2

for asin, lvl in pairs:
    r = mcp__ss_mcp__asin_competitor({
        "marketplace": "US",
        "asin": asin,
        "size": 20
    })
    # 记录每个候选的来源 ASIN 和层级
```

**只扩一跳。** 二阶扩池的边际收益很低，噪声却指数上升。

### 过滤规则

| 规则 | 动作 |
|---|---|
| 站点不同 | 丢弃 |
| 类目路径前 3 段不一致 | 丢弃（跨类目的"竞品"没有参考价值） |
| `units` < 100 | 丢弃（无销量 = 无稳定词结构） |
| `units` 为 `null` | **不要当 0 丢弃**——Amazon 自营和私牌的销量接口不返回，标 `DATA_MISSING` 后保留 |
| 同品牌不同 ASIN | 归组，**不参与词频**，只在报告里标注"变体" |
| 形态明显不同 | **保留**，标 `formDiff=true`，后面算差异化时用 |

### 补池

`asin_competitor` 扩不满 8 个时，用类目补：

```python
mcp__ss_mcp__product_research({
  "request": {
    "marketplace":"US",
    "nodeIdPath":"<类目前三段>",
    "minUnits": 200,
    "size": 50
  }
})
```

从结果里按销量取 Top 10，层级标 L2（权重 0.5）。

**别指望 `competitor_lookup` 扩池**：实测 `page` / `size` 参数都被忽略，永远只给第 1 页 5 条（`total` 字段是真的）。

### 输出：竞品池表

| ASIN | 品牌 | 层级 | 权重 | 月销 | 价格 | 评分 | 评分数 | 形态 | formDiff | 来源 |
|---|---|---|---|---|---|---|---|---|---|---|

**池子目标 8-15 个。** 少于 5 个 → 报告里写"样本不足，词频仅供参考"。

## A2. 榨词（反查出单词）

### 用哪个工具（2026-11-13 实测）

| 工具 | 实测结果 | 结论 |
|---|---|---|
| `traffic_keyword` | ✅ 正常返回词、搜索量、自然位、广告位、流量占比 | **主力，就用它** |
| `keyword_order` | ❌ 多个 ASIN、周/月口径全试过，`total: 0` | **别用，拿不到数据** |

`keyword_order` 在文档里承担「转化分层」的职责，实测拿不到东西，所以本模块不依赖它。

### 调用

```python
for asin in pool:
    mcp__ss_mcp__traffic_keyword({
        "request": {"marketplace":"US", "asin":asin, "size":50}
    })
    # 翻页直到 hasNextPage = false
```

**词量差异极大，必须先看 `total`**：实测同一类目下，一个 ASIN 只有 13 个词，另一个 1,724 个。`total < 30` 时，这个 ASIN 的词表只能当补充，不能当主力样本；`total > 50` 必须翻页，否则拿到的是截断样本。

### 返回里要先过滤一层

`traffic_keyword` 会混进**完全不相关的词**。实测：一个壁挂衣帽架的 ASIN，词表里出现了 "toilet caps"。

这不是接口错，是它把同一父体或同一次广告投放的搜索词全捞进来了。所以拿回来第一件事是**按 R1 品类相关过滤**（见 `05-合并打分输出.md`），不要直接进词库。

### 转化分层怎么办

`traffic_keyword` 里有 `conversionKeywordType` 字段（值可能是 `excellent` / `stable` / `lost` / `invalid`）。实测两种都有：有的 ASIN 有值（stable / excellent），有的全为 `null`，按它筛选时空结果常见。

所以：

- 字段有值 → 用，按 E/S/L/I 分档
- 字段为 `null` → **不要猜**，在报告里标 `DATA_MISSING: 转化分层`
- 想补这一块 → 让用户上传**广告搜索词报告**（见 `00-input/README.md` 第 3 节），那是唯一可靠的真实转化来源

### 「有流量但接不住」的机会点

这个判断原本靠 `keyword_order` 的 L 型词，现在换一种做法：

| 信号 | 怎么看 | 含义 |
|---|---|---|
| 搜索量高、自然位靠后 | `searches` 高 + `rankPosition.position` > 60 | 竞品排名不行，有空间 |
| 流量占比低 | `trafficPercentage` 很小但搜索量大 | 竞品没吃到这个词 |
| 广告位靠前、自然位缺席 | `adPosition` 有值、`rankPosition` 为 null | 纯靠钱买的位置，一旦停投就掉 |

这三条任意命中一条，都能替代原来「L 型词」的作用，而且全部来自实测拿得到的字段。

### 输出：竞品词表

| keyword | 来源 ASIN | 层级 | 搜索量 | 自然位 | 广告位 | 流量占比 | 转化分层（可空） | 出现在几个竞品 |
|---|---|---|---|---|---|---|---|---|

**「出现在几个竞品」是最重要的列**——一个词被 8 个竞品同时吃，说明它是品类基础词；只有 1 个竞品吃，可能是它的品牌词或独特打法。

---

## 注意事项

1. `traffic_keyword` 单次最多回 50 条；`total` 大于 50 就翻页，别用 `size=500` 硬拉。
2. `rankPosition` / `adPosition` 是对象，取 `.position`，不是直接的数字。
3. 自家 ASIN 也跑一遍，用来做「竞品有、我没有」的差集——这是最直接的补词清单。
4. **先信 `total`，再信词表**：返回 13 条和返回 270 条，可信度不在一个量级。
