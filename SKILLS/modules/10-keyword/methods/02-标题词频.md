# 方法 B：竞品标题词频

> 导图子项：竞品标题高频词

**标题是竞品最贵的一块地。** 75 字符里放什么词，是卖家真金白银试出来的取舍。所以标题词频 = 行业共识，可信度高于任何"我觉得"。

---

## 步骤

### 1. 取标题

```python
for p in pool:
    mcp__ss_mcp__asin_detail({"marketplace":"US", "asin":p["asin"]})
    # 取 title 字段
```

### 2. 落成 JSON

```json
[
  {"asin":"B0XXXX", "level":0,   "title":"..."},
  {"asin":"B0YYYY", "level":1,   "title":"..."},
  {"asin":"B0ZZZZ", "level":1.5, "title":"..."}
]
```

`level` 对应 `00-input` 的权重：0 → ×3、1 → ×1、1.5 → ×2、2 → ×0.5。

### 3. 跑脚本

```bash
python scripts/freq.py products.json \
  --weight-l0 3 --weight-other 1 \
  --min-asin 2 --top 100 --out title_freq.csv
```

标题模式下建议 `--min-asin 2`：只出现 1 次的词大概率是某个竞品的独特打法，进不了"共识"，但可能是差异化机会，所以**单独留一份 `--min-asin 1` 的结果**做差异分析。

---

## 权重怎么算的

脚本内部三层叠加：

```
词得分 = Σ(ASIN 权重 × 字段权重) × IDF
```

| 层 | 值 | 理由 |
|---|---|---|
| ASIN 权重 | L0=3 / L1.5=2 / L1=1 / L2=0.5 | 用户选的头部竞品说话更响 |
| 字段权重 | 标题 3 / 五点 2 / 描述 1 | 标题是精选结果，描述是铺陈 |
| IDF | `log((N+1)/(df+1)) + 1` | 覆盖越广越像通用词，权重回收 |

**为什么用 IDF 而不是直接数频次**：如果只数次数，"for / with / set" 这类无意义高频词会霸榜。IDF 让"只在少数竞品出现但每次都有"的词浮上来。

---

## 结果怎么读

| 现象 | 含义 | 动作 |
|---|---|---|
| `coverage` 高 + `l0_asin_count ≥ 1` | 品类核心词，头部竞品都在用 | P0，进标题 |
| `coverage` 高 + `l0_asin_count = 0` | 行业通用词，但你的头部竞品没强调 | P1，进 Highlights 或五点 |
| `coverage` < 0.3 + `l0_asin_count ≥ 1` | **差异化词**，你在用、别人少用 | Highlights 首选 |
| `coverage` < 0.3 + `l0_asin_count = 0` | 个别竞品的独特打法 | 看是否可复制，不可复制就忽略 |

**第三行是本次调研的核心产出之一**，直接喂给 `40-copy` 的 Highlights。

---

## 常见坑

| 坑 | 表现 | 解法 |
|---|---|---|
| 品牌词干扰 | 自家品牌名占据 Top 3 | 先把品牌词剔除再统计 |
| 变体重复计数 | 同一个产品 5 个变体 ASIN 全进池 | 同品牌同款只保留 1 个代表 |
| 停用词漏删 | "with" "for" 排前面 | `freq.py` 内置停用词表，不够就补 |
| 单复数不合并 | "hook" 和 "hooks" 分开算 | 默认不合并（Amazon 索引也不完全合并），但报告里注明 |
| 标题长度差异 | 有的竞品标题塞满 200 字符，有的只有 40 | 统计前不做长度归一，改为在报告里标注异常值 |

## 输出

`title_freq.csv`：

| 列 | 含义 |
|---|---|
| `word` | 词或词组（1-3 gram） |
| `weighted_score` | 加权得分 |
| `raw_count` | 原始出现次数 |
| `asin_count` | 出现在几个 ASIN 里 |
| `coverage` | 覆盖率（asin_count / 总数） |
| `l0_asin_count` | 出现在几个用户提供的 ASIN 里 |
| `in_title` / `in_bullets` / `in_description` | 分字段加权分 |

**同一份结果同时给了标题、五点、描述的分数**，所以方法 B 和 C 其实跑一次脚本就够了——只是看的列不同。
