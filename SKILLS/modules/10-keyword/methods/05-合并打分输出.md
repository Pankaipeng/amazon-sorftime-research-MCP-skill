四路跑完后，这一步把碎片拼成能用的东西。

## 一、合并去重

### 归一化

```
小写 → 去标点 → 合并多余空格 → 去首尾空格
```

`Shoe Rack` / `shoe  rack` / `shoe-rack` 归为同一个词。

**不合并单复数**："hook" 和 "hooks" 在 Amazon 索引里是分开的，合并会丢信息。但报告里要注明这条规则。

### 来源标记

每个词记一个 `sources` 字段，多个来源按字母顺序拼在一起（如 `ADNS`）：

| 标记 | 来源 | 可信度含义 |
|---|---|---|
| `A` | 竞品流量词 / 出单词 | 有真实曝光或转化 |
| `B` | 竞品标题词频 | 有行业共识 |
| `C` | 竞品 Listing 词频 | 有卖点表达 |
| `D` | 前台自动补全 | 有真实搜索行为 |
| `S` | 卖家精灵 `keyword_miner` 搜索量 | 有量，但**这一路主要供"量"，不是"发现词"的方法**；只在 S 里出现的词属单源，可信度最低 |
| `N` | 商机探测器（Niche 搜索词表） | 官方口径，有搜索转化率 |
| `E` | ABA 热门搜索词 | 官方排名，只有排名没有绝对值 |

> **为什么要拆 N 和 E**：两者都属"后台报表"，但 Niche 给的是搜索量与转化率，ABA 给的是排名与点击份额，用途不同，合并成一个 `E` 会看不出这个词到底被哪张表证实过。
>
> **为什么要单列 S**：搜索量是补量环节的副产品，不是发现新词的渠道。实测 235 个词里有 35 个只出现在 S 里——前四路都没抓到，只有一个搜索量数字，这种词要标"单源"。

**多源本身是强信号。** 字母越多越可信：`ADNS`（四路见过）远强于 `S`（只有搜索量）。在最终评分里可以给个小加成：`源数 ≥ 3` 时 R 加 0.05，上限 1.0。

## 二、补指标

搜索量未知的词，批量丢给 `keyword_miner`：

```python
mcp__ss_mcp__keyword_miner({
  "request": {
    "marketplace": "US",
    "keywordList": ["词1","词2","..."]   # 一次 ≤50 个
  }
})
```

取回字段：

| 字段 | 含义 | 用途 |
|---|---|---|
| `searches` | 月搜索量 | W 的主因子 |
| `purchases` | 月购买量 | 校验需求真实性 |
| `purchasesRate` → 实际字段 **`purchaseRate`** | 购买率 | 转化意图强度 |
| `spr` | 上首页所需销量/评论 | 进入成本 |
| `titleDensity` | 标题密度 | 竞争饱和度 |
| `monopolyClickRate` | 点击集中度 | 是否被头部垄断 |
| `bid` | PPC 建议竞价 | 广告成本 |
| `avgPrice` | 均价 | 价格带判断 |
| `supplyDemandRatio` | 供需比 | 蓝海判断 |

**查不到的词**标 `EST`，用 `ac_score` 做代理，不要编数字。实测 `keywordList` 精确查询 32 个词，有 7 个返回 `searches: null`（钽长尾），属正常。

## 三、口径校验

导图上写了"多口径用于数据校验，结果需去重处理"。具体怎么做：

### 四个口径的关系

| 口径 | 来源 | 特征 | 拿不到时 |
|---|---|---|---|
| 卖家精灵 | `keyword_miner` | 月粒度估算，覆盖广 | — |
| ABA | 品牌分析 | 官方搜索频率排名，只有排名没有绝对值 | 标 `DATA_MISSING` |
| 后台商机探测器 | 卖家后台 | 类目推荐词，含搜索量区间 | 标 `DATA_MISSING` |
| **自有后台报表** | **用户上传的附件** | 自己的曝光、点击、**订单**、退货 | 标「后台数据：未提供」 |

**前三个是市场侧，第四个是自己的账户侧。四个都不能相加，也不能互相替代。** 差值 3-5 倍是常态。

第四行要特别说明：卖家精灵 MCP **拿不到**你店铺的广告报告和业务报告，这部分必须由用户导出后上传（见 `00-input/README.md` 第 3 节）。它对准确性的影响最大，因为它是唯一带真实转化的数据。

### 校验规则

| 情况 | 处理 |
|---|---|
| 卖家精灵有值、ABA 排名也靠前 | 高可信，正常用 |
| 卖家精灵有值、ABA 查不到 | 可能是长尾或新词，标"单源" |
| 卖家精灵无值、ABA 有排名 | 用 ABA 排名做相对排序，搜索量标 `EST` |
| 两者趋势相反 | **危险信号**，报告里单独提，不要下结论 |
| **后台报表有订单 + 卖家精灵有搜索量** | 双向印证，**直接进 P0**，优先级高于纯估算词 |
| **后台报表有曝光、订单为 0** | 否定候选，**优先于模型判断**（真金白银试过的结论） |
| **后台报表有、卖家精灵查不到** | 新词或超长尾，用报表数据兜底，标 `sources=E` 单源 |
| **后台报表没传** | 不阻塞，但口径声明里写清"转化类结论未验证" |

### 只在报告里写一句

```markdown
口径校验：137 个词中，112 个有卖家精灵搜索量；
其中 89 个在 ABA Top 100k 内，方向一致；
3 个出现方向背离（见附录），已标注但不用于决策。
```

## 四、相关性 R

```
R = 0.5 × R1 + 0.3 × R2 + 0.2 × R3
```

| 分量 | 判定 | 打分 |
|---|---|---|
| **R1 品类相关** | 词是否直接指向本品品类 | 1 = 是；0.5 = 相关品类；0 = 否 |
| **R2 属性匹配** | 词里的属性与本品事实卡是否一致 | 1 = 一致；0.5 = 部分；0 = **冲突** |
| **R3 市场共识** | = 竞品覆盖率 `coverage`（方法 B/C 输出） | `min(1, coverage / 0.6)` |

**R3 要归一化，不能直接用覆盖率。** 实测：泛词的覆盖率能做到 0.9，长尾词只有 0.2。如果直接拿 coverage 当 R3，长尾词的 R 会被压到 0.6 以下，全部掉进 P2/P3，明明很精准的词反而排最后。

约定 **覆盖率 60% 记满格**（`min(1, cov/0.6)`）：出现在 6 成竞品标题里就算行业共识，再多也不加价。

> 实测（壁挂海绵架）：`sponge holder for kitchen sink` 覆盖率 0.933 → R3=1.0；`sink caddy` 0.5 → R3=0.833；某个长尾 0.2 → R3=0.333。

**没有覆盖率数据时 R3 给 0.5**（中性），不要给 0——那不是"没有共识"，是"没测"。

**R1 或 R2 为 0 的词直接进否定清单**，不参与后续排序。典型冲突：

- 本品 wall mount，词是 freestanding → R2=0
- 本品 wood，词是 metal → R2=0
- 本品透明，词是 black / matte black → R2=0（实测案例：本品 Clear，`black kitchen accessories` 月搜 10,064，必须否掉）
- 本品 5 hooks，词是 8 hooks → R2=0.5（相关但不同规格）

### R2 里必须有一项「形态」

形态（安装方式）不是一个普通属性，它是**买家最先筛掉的那一维**。词里带不带形态词，决定搜出来的是不是同一类东西。

| 形态判定 | R2 | 依据词 |
|---|---|---|
| **同形态** | 1.0 | 词里带本品的安装方式：suction / adhesive / in sink / wall / hanging / faucet |
| **泛词（形态混合）** | 0.5 | 无形态限定，搜索结果里几种形态混着 |
| **异形态** | 0 | 词里带对立形态：countertop / tray / freestanding / extendable |

**实测（壁挂海绵架）**：`sponge holder for kitchen sink` 是全类目最大词（月搜 167,620），但搜索结果台面款占比高。上一版给 R2=1.0，被当成"精准核心词"；加形态维度后 R2=0.5、R=0.85（若按满分算应为 1.0），降为"必须占位但不能只靠它"。

**这一项的理由要写进报告**：不是"这个词不相关"，而是"这个词相关但不精准，需要再补一个形态限定词"。

**R1/R2 是判断不是数据，必须写依据。** 报告里每行标 `JUDGED: 依据=...`。

## 五、权重 W

```
有搜索量：  W = searches × R
无搜索量：  W = ac_score × R × 10        （EST 词，把 ac_score 拉到千级量级）
```

为什么用乘积：搜索量再大，相关性为 0 就是 0 分。加和会让大词永远排第一。

**W 只用于排序，不要拿绝对值比较不同类目**——不同类目的搜索量基数差一个数量级。

## 六、分层（导图输出层之一）

| 层级 | 判定 | 说明 |
|---|---|---|
| **大词** | 搜索量 ≥ P75 且 R < 0.8 | 泛，点击分散，前期不碰 |
| **核心词** | R ≥ 0.8 且 搜索量 ≥ P50 | 标题主力 |
| **长尾词** | 搜索量 < P50，或 词数 ≥ 4 且 搜索量 < P75 | ST、QA、五点埋词 |

**阈值必须写进报告**。类目不同，Top 10% 的绝对值可能差 100 倍，所以用**分位数**不用绝对值。

判定顺序（从上往下，命中即停）：

1. 搜索量 ≥ P75 且 R < 0.8 → 大词
2. R ≥ 0.8 且 搜索量 ≥ P50 → 核心词
3. 其余 → 长尾词

**词数只能当辅助条件，不能单独判定。** 实测踩过坑：`sponge holder for kitchen sink` 有 5 个词，按「词数 ≥ 4 → 长尾」直接判错——它月搜索 167,620，是全类目头部词。

## 七、优先级（导图输出层之二）

按 W 降序排名后分档，**和层级是两个独立维度**：

| 档 | 条件 | 动作 | 典型组合 |
|---|---|---|---|
| **P0** | W 前 10 且 R ≥ 0.8 **且 搜索转化率 ≥ 2%** | 标题、Highlights | 核心词 + P0 |
| **P1** | W 11-40 或 R 0.6-0.8 或 转化率 < 2% | 五点、A+ | 核心词 + P1 |
| **P2** | R ≥ 0.5 | ST、QA | 长尾词 + P2 |
| **P3** | R < 0.5 但 > 0 | 观察，不投 | 大词 + P3（等你做大再说） |
| **NEG** | R1=0 或 R2=0 | 否定清单 | — |
| **BRAND** | 竞品品牌词 | 单列 | — |

**转化率那一票是否决票，不是加分项。** 有后台报表时，搜索转化率 < 2% 的词不管搜索量多大都不能进 P0——那是"泛收纳"流量，买的人要的不一定是本品。

实测（壁挂海绵架）：`kitchen sink organizer` 月搜 98,007、转化 1.88%，`kitchen sink accessories` 月搜 71,536、转化 0.69%，两个都被从 P0 踢到 P1。同一批里 `sponge holder for sink` 月搜只有 21,755，但转化 5.33%，稳稳 P0。

**没有后台报表时不套这条**（拿不到转化率就不能罚），但要在口径声明里写明"P0 仅按搜索量与相关性排序"。

**大词 + P3 是正常状态**，不是漏掉了。前期把钱花在核心词和长尾词上，等销量起来再打大词。

## 十、两条硬规则（2026-11-13 实测补充）

### 1. EST 词不参与 P0/P1

`keyword_miner` 查不到搜索量的词，用 `ac_score × R × 10` 估个 W 是可以的，但**这个 W 和实测 W 不是一个量纲**，不能混在一张榜上排序。

实测：118 条自动补全词里有 111 条查不到搜索量。如果让它们和实测词一起排，`ac_score` 高的长尾会压过真实有量的词。

处理：

```
有搜索量 → MEASURED，正常参与 P0-P3
只有 ac_score → EST，最高给 P2，一律排在 MEASURED 之后
两样都没有 → NODATA，单列"待补量"，不参与排序
```

**EST 占比超过 40% 要写进报告**，并说明原因（通常是方法 D 采集过宽，或品类本身搜索量极低）。别装作词库里全是实测词。

### 2. 太泛的词不能进否定清单

R1=0 只说明"不是本品"，不说明"该否定"。**否定一个比本品更宽泛的词，会连正常流量一起挡掉。**

实测踩过的坑：`kitchen sink`、`suction cup`、`stainless steel`、`adhesive strips`、`smiley face` 都算 R1=0，但它们是把整个类目都包住的大词。放进否定清单等于关掉一半入口。

处理：设一个 `NO_NEG` 白名单，这类词标记"观察"，不进 `negative_words.txt`。

**进否定的三类才安全**：对立形态（countertop / tray / freestanding）、冲突属性（材质、颜色、尺寸）、异类商品（soap dish / cleaning caddy）。

## 十一、合并追踪（证明每条路真的被消费）

词库交付时必须附一张 `00-五路合并追踪.csv`，逐路写清：产出多少词、进了候选多少、进了词库多少、其中多少进了 P0/P1、多少进了否定。

不附这张表的词库**无法验证是不是真的合并过**——最常见的问题是：方法 B/C/D 各自出了 CSV，但最终词库其实是人工维护的清单，三份产出根本没进去。

实测（壁挂海绵架，262 条产出 → 235 条入库）：

| 来源 | 产出 | 进词库 | 进 P0/P1 |
|---|---|---|---|
| A 竞品流量词 | 15 | 15 | 12 |
| B 标题词频 | 45 | 19 | 6 |
| C Listing 代理 | 23 | 8 | 1 |
| D 自动补全 | 118 | 118 | 2 |
| E Niche | 20 | 20 | 19 |
| E ABA | 41 | 41 | 20 |

**这张表本身就是结论**：五路重合度极低。D 路 118 条只有 2 条进得了 P0/P1——不是 D 没用，而是它拿到的是"真实存在但没搜索量"的长尾，战场在 QA/ST。如果某一路的"进词库"是 0，要么参数错，要么那一路没跑对。
