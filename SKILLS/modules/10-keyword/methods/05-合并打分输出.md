# 合并、打分、输出

四路跑完后，这一步把碎片拼成能用的东西。

---

## 一、合并去重

### 归一化

```
小写 → 去标点 → 合并多余空格 → 去首尾空格
```

`Shoe Rack` / `shoe  rack` / `shoe-rack` 归为同一个词。

**不合并单复数**："hook" 和 "hooks" 在 Amazon 索引里是分开的，合并会丢信息。但报告里要注明这条规则。

### 来源标记

每个词记一个 `sources` 字段，多源用 `|` 连接：

| 标记 | 来源 | 可信度含义 |
|---|---|---|
| `A` | 竞品流量词 / 出单词 | 有真实曝光或转化 |
| `B` | 竞品标题词频 | 有行业共识 |
| `C` | 竞品 Listing 词频 | 有卖点表达 |
| `D` | 前台自动补全 | 有真实搜索行为 |
| `E` | 广告搜索词报告（可选） | **有真实转化，最可信** |

**多源本身是强信号**。一个词同时有 A+C+D，比单源词值得多投一分。在最终评分里给个小加成：`源数 ≥ 3` 时 R 加 0.05，上限 1.0。

## 二、补指标

搜索量未知的词，批量丢给 `keyword_miner`：

```python
mcp__ss_mcp__keyword_miner({
  "request": {
    "marketplace": "US",
    "keywordList": ["词1","词2","..."]   # 一次建议 ≤50 个
  }
})
```

取回字段：

| 字段 | 含义 | 用途 |
|---|---|---|
| `searches` | 月搜索量 | W 的主因子 |
| `purchases` | 月购买量 | 校验需求真实性 |
| `purchasesRate` | 购买率 | 转化意图强度 |
| `spr` | 上首页所需销量/评论 | 进入成本 |
| `titleDensity` | 标题密度 | 竞争饱和度 |
| `monopolyClickRate` | 点击集中度 | 是否被头部垄断 |
| `bid` | PPC 建议竞价 | 广告成本 |
| `avgPrice` | 均价 | 价格带判断 |
| `supplyDemandRatio` | 供需比 | 蓝海判断 |

**查不到的词**标 `EST`，用 `ac_score` 做代理，不要编数字。

## 三、口径校验

导图上写了"多口径用于数据校验，结果需去重处理"。具体怎么做：

### 三个口径的关系

| 口径 | 来源 | 特征 |
|---|---|---|
| 卖家精灵 | `keyword_miner` | 月粒度估算，覆盖广 |
| ABA | 品牌分析 | 官方搜索频率排名，只有排名没有绝对值 |
| 后台商机探测器 | 卖家后台 | 类目推荐词，含搜索量区间 |

**它们不能相加，也不能互相替代。** 差值 3-5 倍是常态。

### 校验规则

| 情况 | 处理 |
|---|---|
| 卖家精灵有值、ABA 排名也靠前 | 高可信，正常用 |
| 卖家精灵有值、ABA 查不到 | 可能是长尾或新词，标"单源" |
| 卖家精灵无值、ABA 有排名 | 用 ABA 排名做相对排序，搜索量标 `EST` |
| 两者趋势相反 | **危险信号**，报告里单独提，不要下结论 |

### 只在报告里写一句

```markdown
口径校验：137 个词中，112 个有卖家精灵搜索量；
其中 89 个在 ABA Top 100k 内，方向一致；
3 个出现方向背离（见附录），已标注但不用于决策。
```

## 四、相关性 R

```
R = 0.5 × R1 + 0.3 × R2 + 0.2 × R3
```

| 分量 | 判定 | 打分 |
|---|---|---|
| **R1 品类相关** | 词是否直接指向本品品类 | 1 = 是；0.5 = 相关品类；0 = 否 |
| **R2 属性匹配** | 词里的属性与本品事实卡是否一致 | 1 = 一致；0.5 = 部分；0 = **冲突** |
| **R3 市场共识** | = 竞品覆盖率 `coverage`（方法 B/C 输出） | 0-1 直接用 |

**R1 或 R2 为 0 的词直接进否定清单**，不参与后续排序。典型冲突：

- 本品 wall mount，词是 freestanding → R2=0
- 本品 wood，词是 metal → R2=0
- 本品 5 hooks，词是 8 hooks → R2=0.5（相关但不同规格）

**R1/R2 是判断不是数据，必须写依据。** 报告里每行标 `JUDGED: 依据=...`。

---

## 五、权重 W

```
有搜索量：  W = searches × R
无搜索量：  W = ac_score × R × 10        （EST 词，把 ac_score 拉到千级量级）
```

为什么用乘积：搜索量再大，相关性为 0 就是 0 分。加和会让大词永远排第一。

**W 只用于排序，不要拿绝对值比较不同类目**——不同类目的搜索量基数差一个数量级。

---

## 六、分层（导图输出层之一）

| 层级 | 判定 | 说明 |
|---|---|---|
| **大词** | 搜索量在样本 Top 10% 且 R < 0.8 | 泛，点击分散，前期不碰 |
| **核心词** | R ≥ 0.8 且搜索量中位以上 | 标题主力 |
| **长尾词** | 搜索量后 50%，或词数 ≥ 4 | ST、QA、五点埋词 |

**阈值必须写进报告**。类目不同，Top 10% 的绝对值可能差 100 倍，所以用**分位数**不用绝对值。

判定顺序（从上往下，命中即停）：

1. 词数 ≥ 4 → 长尾词
2. R < 0.8 且搜索量 ≥ P90 → 大词
3. R ≥ 0.8 且搜索量 ≥ P50 → 核心词
4. 其余 → 长尾词

---

## 七、优先级（导图输出层之二）

按 W 降序排名后分档，**和层级是两个独立维度**：

| 档 | 条件 | 动作 | 典型组合 |
|---|---|---|---|
| **P0** | W 前 10 且 R ≥ 0.8 | 标题、Highlights | 核心词 + P0 |
| **P1** | W 11-40 或 R 0.6-0.8 | 五点、A+ | 核心词 + P1 |
| **P2** | R ≥ 0.5 | ST、QA | 长尾词 + P2 |
| **P3** | R < 0.5 但 > 0 | 观察，不投 | 大词 + P3（等你做大再说） |
| **NEG** | R1=0 或 R2=0 | 否定清单 | — |
| **BRAND** | 竞品品牌词 | 单列 | — |

**大词 + P3 是正常状态**，不是漏掉了。前期把钱花在核心词和长尾词上，等销量起来再打大词。

## 八、输出三件套

### 1. `keyword_library.csv`

```
keyword, level, priority, W, R, R1, R2, R3,
searches, purchases, purchases_rate, spr, title_density,
monopoly_click_rate, bid, avg_price,
sources, l0_hit, coverage, ac_score, est_flag, confidence
```

- `level`：大词 / 核心词 / 长尾词
- `priority`：P0 / P1 / P2 / P3 / NEG / BRAND
- `confidence`：MEASURED / DERIVED / JUDGED / EST

按 `priority` 再按 `W` 降序。

### 2. `negative_words.txt`

一行一个，直接粘广告后台。只放 R1=0 或 R2=0 的，不要把 P3 放进去——P3 是"以后可能做"，不是"永远不做"。
