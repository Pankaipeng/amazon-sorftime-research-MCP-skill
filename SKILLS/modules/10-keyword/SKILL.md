# 10 · 关键词调研

> 导图对应：处理层「关键词调研」5 个子项 → 输出层「关键词层级 + 排序优先级」。

这是一个**模块**，不是一个一次性脚本。五路是并集，缺哪路就标缺失，不要用别的路凑。

---

## 输入

从 `00-input/` 取三样：

| 输入 | 用途 |
|---|---|
| 竞品 ASIN 组（head / direct / new 三类） | 方法 A/B/C 的样本，也是权重来源 |
| 本品事实卡 | 算相关性 R 的品类与属性依据 |
| **后台数据（用户上传：商机探测器 + ABA）** | 搜索转化率、真实排名、趋势 |

**没有事实卡就先跑不了。** "这个词相关不相关"没有事实卡就是拍脑袋。

**后台数据 MCP 拿不到，只能由用户导出上传。** 它可选，但强烈建议——这是唯一带真实转化率的一手数据，也决定 P0 排序准不准。取用方式见 `00-input/README.md` 第 3 节。

---

## 五路方法

| # | 方法 | 产出 | 强项 | 弱项 |
|---|---|---|---|---|
| **A** | 竞品 ASIN 反查 | 竞品真实出单词 + 流量词 | 有真实曝光信号 | 只覆盖已有竞品 |
| **B** | 竞品标题词频 | 行业共识词 | 反映关键词取舍 | 只看到精选后的词 |
| **C** | 竞品 Listing 词频 | 卖点表达词、痛点词 | 抓得到"买家语言" | 要取 `features` 字段（不是 bullets）；多为句子成分，只作证据和素材 |
| **D** | 前台自动补全 | 当下真实搜索词、长尾 | 反映即时搜索行为 | 无搜索量，每次只 10 条 |
| **E** | 后台报表（用户上传：商机探测器 + ABA） | 真实排名、搜索转化率、趋势 | 唯一带真实转化率 | 只有用户能导出 |

**A 扩池、B/C 提取共识、D 补长尾、E 验证转化。** 五路互相校验，不互相替代。

> **实测提醒（2026-11-13 两次修正）**：五点在 `asin_detail` 里叫 **`features`**（字符串数组），不叫 `bullets` / `bulletPoints` / `featureBullets`——按后者取名一律返回 null，会误判成"接口不给五点"。实测 30 个壁挂竞品 30/30 都取得到，共 164 条。**`description` 仍然拿不到（null）**，所以方法 C 只做五点，不做描述。详见 `methods/03-listing词频.md`。

- `methods/02-标题词频.md`
- `methods/03-listing词频.md`

## 执行顺序

```
0. 读 00-input，确认三类 ASIN + 事实卡齐全
1. 方法 A：扩池。三步都要做——asin_competitor 扩一层 + 类目 product_research（variation:"Y"）销量 Top + 按形态过滤剔掉台面竞品
2. 批量拉 asin_detail，落 products.json（**要 `features` 字段，五点在这里**）
3. 方法 B/C：跑 freq.py --strip-brands，出标题词频 + 五点词频；三点词另跑正则出 `03b`
4. 方法 D：选 1-3 个种子词，跑 ac.py 生成请求清单，逐个 web_fetch
5. 方法 E：有后台报表就做三口径对账，补搜索转化率与趋势
6. keyword_miner 批量补搜索量/SPR/标题密度/PPC，**落成 `06-搜索量底表.csv`**（不许写死在代码里）
7. 跑 `scripts/merge.py <项目目录>`：读 config.yaml + 五路产出 → 分层 → 优先级 → 词库/否定/品牌词/追踪表
8. 跑 `scripts/check.py <项目目录>`：7 项自检全过才算完成，不过就不许交
9. 写 handoff.md
```

**步 7 之前不要做任何判断**，先把词凑齐。凑不齐时"哪个词重要"的判断都是假的。

**步 7 和 8 是两条硬边界**：`merge.py` 里不允许出现任何硬编码的词或数字（全在 `config.yaml`），`check.py` 不过就不交付。加这两条的原因是——前几版打分脚本里的词表是写死的常量，五路产出各出了 CSV 却没进词库，D 路 118 条只进了 5 条。

## 输出（对应导图输出层）

**四个方法的原始产出必须各出一份，不能只交合并表。** 这是用户明确提过的要求：

| 文件 | 内容 |
|---|---|
| `0A-竞品流量词.csv` | 方法 A 的真实流量词 + 流量占比 |
| `01-竞品ASIN库.csv` | 方法 A 扩池结果，带层级、权重、**安装形态**、来源 |
| `01b-排除的台面竞品.csv` | 按形态过滤掉、未入池的竞品，留档备查 |
| `02-标题高频词.csv` | 方法 B 词频，已剔品牌 |
| `02b-竞品标题原文.csv` | **30 条竞品标题整条原文**——R3 覆盖率的分母，不能省（见下） |
| `03-Listing高频词.csv` | 方法 C 五点词频（`in_bullets` 分列），给已发现的词补证据 |
| `03b-三类词抽取.csv` | 痛点 / 证据 / 限制 三类说法 + 覆盖数，直接喂五点与 QA |
| `04-自动补全词表.csv` | 方法 D 全部联想词 + 词类标注 |
| `05-后台数据对标.csv` | 方法 E 三口径对账表 |
| `06-搜索量底表.csv` | 补量结果落盘（keyword, searches, source），**只存一期**，脚本只读这个文件 |
| `07-竞争度底表.csv` | spr / monopoly_click_rate / title_density / products，供四象限用 |
| `07b-词根映射.csv` | 本次词库 token 分布现场归纳的词根六分类表，换类目重生成 |
| `00-五路合并追踪.csv` | **每条路产出多少词、进词库多少、进 P0/P1 多少——证明五路真被消费过** |
| `keyword_library.csv` | 合并词库 |
| `negative_words.txt` / `brand_words.txt` | 否定清单 / 竞品品牌词（单列，不否不定） |
| `08-交付自检.txt` | `check.py` 的 7 项自检结果 |

**为什么 `02b` 是必需的。** `02-标题高频词.csv` 只统计到 3 个词的组合，超过 3 个词的短语取不到覆盖率，就退回中性 0.5。实测 235 个词里有 210 个（89%）卡在这个占位分上——相关性里 0.2 的权重九成时候是白给的。只有把 30 条标题原文整条存下来、拿词逐条比对，覆盖率才是真的。别为了省一张表让整列数据空转。


**`00-五路合并追踪.csv` 和 `08-交付自检.txt` 不能省。** 没有追踪表就无法证明词库是五路合并出来的，而不是人工维护的一张清单——实测踩过：前四路各出了 CSV，最终词库却是手工整理的 87 词，三份产出根本没进去。

### 两个维度分开看

导图把输出拆成「关键词层级」和「排序优先级」两块，这两个**必须彻底解耦**：

**层级** = 这个词有多宽 → 只看搜索量，四档
**优先级** = 这个词有多值得做 → 只看 W 排名

早期版本把 R 塞进了层级判定（"R<0.8 才算大词"），一旦相关性算法调整，层级就跟着塌——实测把形态维度去掉后，全员 R≥0.8，大词直接消失。**层级是客观的宽度，不该被主观打分污染。**

### 层级判定（四档，三种切法）

| 模式（`tiers.mode`） | 切法 | 适用 |
|---|---|---|
| **head_relative**（默认） | 本类目最大词为 100%，≥30% 大词 / ≥10% 中词 / ≥3% 小词 / 其余长尾 | 换类目不改参数，自动适配类目大小 |
| **volume_absolute** | ≥10 万 / ≥3 万 / ≥5 千 | 跨类目口径统一，小类目会被压成全是长尾 |
| **percentile** | P80 / P50 / P20 | 词库规模稳定时可用，扩容就漂 |

另有 `tier_abs`：用 ABA 搜索频率排名做全站标尺（≤1 万大词 / ≤10 万中词 / ≤50 万小词），跨类目可比；没有排名时退回类目内层级。

**为什么默认头部比例。** 实测按大盘设 10 万/3 万/5 千，这个类目最大词才 167,620，`sponge holder for sink`（21,755 搜索、转化 5.33%）被压成小词，再叠高竞争判成"不建议打"——而它是壁挂件最准的词之一。绝对锚必须配全站可比指标（ABA 排名），配搜索量会随类目大小失真。

阈值在 `config.yaml` 的 `tiers` 里。**调完必须在报告里写清具体切点。** 没有搜索量的词（EST / NODATA）层级留空，不硬分。


### 优先级（W 降序名额制）

| 档 | 判定 | 动作 |
|---|---|---|
| **P0** | W 排名前 `p0_slots` 个（默认 3） | 标题、Highlights |
| **P1** | 之后 `p1_slots` 个（默认 27） | 五点、A+ |
| **P2** | 其余 | ST、QA、观察 |
| **BRAND** | 竞品品牌词 | 单列，不否定、不投广告、不进标题 |
| **OBSERVE** | R1=0 但过于宽泛 | 只观察，不进否定清单 |
| **NEG** | R1=0 或 R2=0 | 否定清单 |
| **NODATA** | 既无搜索量也无补全位次 | 待补量，不参与排序 |

**名额制，不是绝对阈值。** 早期用"W 前 10 + R≥0.8 + 转化≥2%"三重条件，叠下来只剩 3 个词，既不可控也不可解释。改成名额制后，P0 数量是运营按类目行情定的参数（`p0_slots`），算法只负责排序。

**搜索转化率不参与排序**，只作为词库里的展示列。它是"这个流量纯不纯"的参考，不是"值不值得做"的裁判——尤其在新品期，泛词的高搜索量本身就是价值。

**EST 词（只有 ac_score、没有实测搜索量）最高只给 P2**，一律排在 MEASURED 词之后。两个 W 不是一个量纲，混排会让长尾压过真实有量的词。EST 占比超过 40% 要在 `config.yaml` 里显式确认，并在报告里说明原因。

## 已知限制

| 限制 | 影响 | 处理 |
|---|---|---|
| `keyword_order` 实测返回 0 条 | 竞品转化分层拿不到 | 不用它。改用 `traffic_keyword` 的 `conversionKeywordType`，为空就标 `DATA_MISSING`，靠后台报表补 |
| `asin_detail` 的 `description` 返回 null | 描述拿不到 | 只做五点，不做描述；五点在 **`features`** 字段里，能拿到（实测 30/30） |
| `asin_detail` 的五点字段叫 `features` | 按 `bullets` / `featureBullets` 取名会一律 null，误判成"接口不给五点" | 取字段必须写 `features`；拿到后按句子存进 `bullets` 数组 |
| 五点词频会灌满非搜索词 | 285 条里只有 23 条是搜索词（其余是 `please` / `smooth surface` 这类句子成分） | `c_listing_mode: support_only`（默认）：只补证据，不单独发现词 |
| **`asin_competitor` 会漏掉类目第一** | 实测海绵架类目第一的 Cisily 完全没被扩出来，直接导致差异化结论错误 | **扩池必多一步：按类目 nodeIdPath 拉 `product_research`，按销量降序** |
| **`product_research` 默认带变体，会把样本吃干** | 实测 Cisily 30 个变体占满销量 Top 30，"扩了 30 个"实际只等效 1 个新竞品；9 个 ASIN 的词频把 `smiley face` 误判成独有卖点 | **必传 `variation: "Y"`，并做品牌去重（同品牌 ≤ 2 个）**；样本 < 15 个不判覆盖率 |
| **类目节点里混着不同形态的竞品** | 台面/托盘款的 `tray`、`countertop` 会把壁挂件的词频带偏，混着算出来的差异化是假的 | 扩池时按形态过滤，台面款排除；词频只用同形态样本 |
| **类目节点里混着跨类目噪声** | 实测 100 个候选里 13 个是牛皮纸袋架、吸管架、香蕉钩 | 按 R1 品类相关过滤，标题里没有本品核心名词就丢 |
| **五路产出各出一份、但词库没合并** | 实测前四版词库是手工维护的 87 词，B/C/D 三份产出只进了 3-5 个词 | **必须跑合并脚本，并输出 `00-五路合并追踪.csv`** |
| **形态（壁挂 / 台面）判定不在本技能范围** | R2 只能判材质、颜色这类词面冲突，判不了安装方式；`sink caddy`、`faucet rack` 这类形态模糊的词会给满分 R2 | 形态需要看"这个词底下卖的是什么货"，属商品属性分类，后续由独立 skill 产出标签回填；`config.yaml` 的 `form.enabled` 已预留开关 |
| `product_research` 的 `asins` 参数被忽略 | 不能按 ASIN 批量取数 | 用 `asin_detail` 逐个取 |
| `competitor_lookup` 的 `page`/`size` 被忽略 | 永远只返回 5 条 | 扩池用 `asin_competitor` + 类目 `product_research` |
| `traffic_keyword` 混入无关词 | 实测壁挂衣架的词表里出现 "toilet caps" | 拿回来先按 R1 品类相关过滤 |
| `traffic_keyword` 词量差异极大 | 实测同类目 13 条 vs 1,724 条 | 先看 `total`，< 30 条当补充样本，> 50 条要翻页 |
| Amazon 自营/私牌 `units` 为 `null` | 按「月销 < 100 丢弃」会误杀 | null 不参与销量过滤，标 `DATA_MISSING` 保留 |
| `product_research` 模糊匹配易跑偏 | 实测 `coat rack` 匹配到美甲 `top coat` | 用 `matchType: 3` 精准匹配 |
| `keyword_miner` 对超长尾返回空 | 长尾词没有搜索量 | 用 `ac_score` 当代理，标 `EST`，最高 P2 |
| 自动补全每次只 10 条 | 覆盖有限 | 靠前缀组合凑量，见方法 D |
| `keyword_research` 忽略 keyword 参数 | 不能做精准查询 | 改用 `keyword_miner` 的 `keywordList` |
| 搜索量是估算值 | 绝对值不可信 | 与商机探测器对账后再用；单口径只用于排序 |
