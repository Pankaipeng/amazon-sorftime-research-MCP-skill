# 10 · 关键词调研

> 导图对应：处理层「关键词调研」5 个子项 → 输出层「关键词层级 + 排序优先级」。

这是一个**模块**，不是一个一次性脚本。五路是并集，缺哪路就标缺失，不要用别的路凑。

---

## 输入

从 `00-input/` 取三样：

| 输入 | 用途 |
|---|---|
| 竞品 ASIN 组（head / direct / new 三类） | 方法 A/B/C 的样本，也是权重来源 |
| 本品事实卡 | 算相关性 R 的品类与属性依据 |
| **后台数据（用户上传：商机探测器 + ABA）** | 搜索转化率、真实排名、趋势 |

**没有事实卡就先跑不了。** "这个词相关不相关"没有事实卡就是拍脑袋。

**后台数据 MCP 拿不到，只能由用户导出上传。** 它可选，但强烈建议——这是唯一带真实转化率的一手数据，也决定 P0 排序准不准。取用方式见 `00-input/README.md` 第 3 节。

---

## 五路方法

| # | 方法 | 产出 | 强项 | 弱项 |
|---|---|---|---|---|
| **A** | 竞品 ASIN 反查 | 竞品真实出单词 + 流量词 | 有真实曝光信号 | 只覆盖已有竞品 |
| **B** | 竞品标题词频 | 行业共识词 | 反映关键词取舍 | 只看到精选后的词 |
| **C** | 竞品 Listing 词频 | 卖点表达词、痛点词 | 抓得到"买家语言" | 噪声多，MCP 常拿不到文本 |
| **D** | 前台自动补全 | 当下真实搜索词、长尾 | 反映即时搜索行为 | 无搜索量，每次只 10 条 |
| **E** | 后台报表（用户上传：商机探测器 + ABA） | 真实排名、搜索转化率、趋势 | 唯一带真实转化率 | 只有用户能导出 |

**A 扩池、B/C 提取共识、D 补长尾、E 验证转化。** 五路互相校验，不互相替代。

> **实测提醒（2026-11-13）**：`asin_detail` 不返回 `bullets` / `description`，方法 C 实际跑不起来。遇到这种情况就只跑方法 B，并在报告里写明「方法 C 未执行」，不要拿标题词频冒充 Listing 词频。

详细方法见：

- `methods/01-竞品词反查.md`
- `methods/02-标题词频.md`
- `methods/03-listing词频.md`

## 执行顺序

```
0. 读 00-input，确认三类 ASIN + 事实卡齐全
1. 方法 A：扩池。三步都要做——asin_competitor 扩一层 + 类目 product_research（variation:"Y"）销量 Top + 按形态过滤剔掉台面竞品
2. 批量拉 asin_detail，落 products.json
3. 方法 B/C：跑 freq.py --strip-brands，出标题词频 + Listing 词频
4. 方法 D：选 1-3 个种子词，跑 ac.py 生成请求清单，逐个 web_fetch
5. 合并去重，标来源（A/B/C/D/E），出 00-五路合并追踪.csv
6. keyword_miner 批量补搜索量、SPR、标题密度、PPC
7. 方法 E：有后台报表就做三口径对账，补搜索转化率与趋势
8. 算相关性 R（含形态维度）→ 算权重 W → 分层（大词/核心词/长尾词）→ 排优先级
9. 输出：四个方法的原始产出 + 合并词库 + 否定词 + 交接单
```

**步 5 之前不要做任何判断**，先把词凑齐。凑不齐时"哪个词重要"的判断都是假的。

## 输出（对应导图输出层）

**四个方法的原始产出必须各出一份，不能只交合并表。** 这是用户明确提过的要求：

| 文件 | 内容 |
|---|---|
| `0A-竞品流量词.csv` | 方法 A 的真实流量词 + 流量占比 |
| `01-竞品ASIN库.csv` | 方法 A 扩池结果，带层级、权重、**安装形态**、来源 |
| `01b-排除的台面竞品.csv` | 按形态过滤掉、未入池的竞品，留档备查 |
| `00-五路合并追踪.csv` | **每条路产出多少词、进词库多少、进 P0/P1 多少——证明五路真被消费过** |
| `02-标题高频词.csv` | 方法 B 词频，已剔品牌 |
| `03-Listing高频词.csv` | 方法 C 词频；拿不到文本时标代理数据 |
| `04-自动补全词表.csv` | 方法 D 全部联想词 + 词类标注 |
| `05-后台数据对标.csv` | 方法 E 三口径对账表 |

**`00-五路合并追踪.csv` 不能省。** 没有它就无法证明词库是五路合并出来的，而不是人工维护的一张清单——实测踩过：前四路各出了 CSV，最终词库却是手工整理的 87 词，三份产出根本没进去。

### 两个维度分开看

导图把输出拆成「关键词层级」和「排序优先级」两块，这两个不是一回事：

**层级** = 这个词有多宽（决定放哪、投多少）
**优先级** = 这个词有多值得做（决定先做谁）

一个词可以是"大词 + P3（先不投）"，也可以是"长尾词 + P0（马上打）"。

### 层级判定

| 层级 | 判定 | 典型特征 | 用途 |
|---|---|---|---|
| **大词** | 搜索量 ≥ P75 且 R < 0.8 | 泛，点击分散，词义宽 | 后期占坑，前期不碰 |
| **核心词** | R ≥ 0.8，搜索量 ≥ P50 | 明确指向本品 | 标题主力、广告主战场 |
| **长尾词** | 搜索量 < P50，或词数 ≥ 4 且搜索量 < P75 | 意图很明确，转化高 | ST、QA、五点埋词 |

阈值是默认值，类目不同要调。**调完必须在报告里写清用了什么阈值。**

> **2026-11-13 实测修正**：原规则「词数 ≥ 4 即算长尾」会把 `sponge holder for kitchen sink`（167,620 搜索、5 个词）判成长尾词。词数只是辅助条件，必须叠加搜索量门槛。大词门槛也从 P90 降到 P75——P90 会把 `kitchen sink accessories`（71,536 搜索）漏成核心词。

### 优先级

按 W 排序后分档：

| 档 | 条件 | 动作 |
|---|---|---|
| P0 | W 前 10 且 R ≥ 0.8 **且 搜索转化率 ≥ 2%** | 标题、Highlights |
| P1 | W 11-40 或 R 0.6-0.8 或 转化率 < 2% | 五点、A+ |
| P2 | R 0.5-0.8 | ST、QA |
| P3 | R < 0.5 但 > 0 | 观察，不投 |
| NEG | R1=0 或 R2=0 | 否定清单 |
| BRAND | 竞品品牌词 | 单列，不算机会 |

**转化率是一票否决，不是加分项**：有后台报表时，搜索转化率 < 2% 的词不管搜索量多大都进不了 P0。实测 `kitchen sink organizer`（98,007 搜索 / 1.88%）和 `kitchen sink accessories`（71,536 搜索 / 0.69%）因此降到 P1。没有报表时不套这条，但要在口径声明里写清。

**EST 词（只有 ac_score、没有实测搜索量）最高只给 P2**，一律排在 MEASURED 词之后。两个 W 不是一个量纲，混排会让长尾压过真实有量的词。EST 占比超过 40% 要在报告里说明原因。

## 口径声明（每次输出必写）

```markdown
## 口径
- 搜索量来源：卖家精灵 keyword_miner（非 ABA，两者不可相加）
- 时间窗：2026-10
- 竞品样本：12 个 ASIN（head 1 / direct 4 / new 1 / 扩池 6）
- 自动补全：30 次请求，去重后 118 词
- 后台数据：已提供 / 未提供（文件名）
- 口径校验：12 个词可对账，头部 4 个差异 ±5% 以内
```

**不写这段的输出视为不合格。**

## 已知限制

| 限制 | 影响 | 处理 |
|---|---|---|
| `keyword_order` 实测返回 0 条 | 竞品转化分层拿不到 | 不用它。改用 `traffic_keyword` 的 `conversionKeywordType`，为空就标 `DATA_MISSING`，靠后台报表补 |
| `asin_detail` 不返回 bullets / description | 方法 C 跑不了 | 只跑方法 B，报告里写明方法 C 未执行 |
| **`asin_competitor` 会漏掉类目第一** | 实测海绵架类目第一的 Cisily 完全没被扩出来，直接导致差异化结论错误 | **扩池必多一步：按类目 nodeIdPath 拉 `product_research`，按销量降序** |
| **`product_research` 默认带变体，会把样本吃干** | 实测 Cisily 30 个变体占满销量 Top 30，"扩了 30 个"实际只等效 1 个新竞品；9 个 ASIN 的词频把 `smiley face` 误判成独有卖点 | **必传 `variation: "Y"`，并做品牌去重（同品牌 ≤ 2 个）**；样本 < 15 个不判覆盖率 |
| **类目节点里混着不同形态的竞品** | 台面/托盘款的 `tray`、`countertop` 会把壁挂件的词频带偏，混着算出来的差异化是假的 | 扩池时按形态过滤，台面款排除；词频只用同形态样本 |
| **类目节点里混着跨类目噪声** | 实测 100 个候选里 13 个是牛皮纸袋架、吸管架、香蕉钩 | 按 R1 品类相关过滤，标题里没有本品核心名词就丢 |
| **五路产出各出一份、但词库没合并** | 实测前四版词库是手工维护的 87 词，B/C/D 三份产出只进了 3-5 个词 | **必须跑合并脚本，并输出 `00-五路合并追踪.csv`** |
| `product_research` 的 `asins` 参数被忽略 | 不能按 ASIN 批量取数 | 用 `asin_detail` 逐个取 |
| `competitor_lookup` 的 `page`/`size` 被忽略 | 永远只返回 5 条 | 扩池用 `asin_competitor` + 类目 `product_research` |
| `traffic_keyword` 混入无关词 | 实测壁挂衣架的词表里出现 "toilet caps" | 拿回来先按 R1 品类相关过滤 |
| `traffic_keyword` 词量差异极大 | 实测同类目 13 条 vs 1,724 条 | 先看 `total`，< 30 条当补充样本，> 50 条要翻页 |
| Amazon 自营/私牌 `units` 为 `null` | 按「月销 < 100 丢弃」会误杀 | null 不参与销量过滤，标 `DATA_MISSING` 保留 |
| `product_research` 模糊匹配易跑偏 | 实测 `coat rack` 匹配到美甲 `top coat` | 用 `matchType: 3` 精准匹配 |
| `keyword_miner` 对超长尾返回空 | 长尾词没有搜索量 | 用 `ac_score` 当代理，标 `EST`，最高 P2 |
| 自动补全每次只 10 条 | 覆盖有限 | 靠前缀组合凑量，见方法 D |
| `keyword_research` 忽略 keyword 参数 | 不能做精准查询 | 改用 `keyword_miner` 的 `keywordList` |
| 搜索量是估算值 | 绝对值不可信 | 与商机探测器对账后再用；单口径只用于排序 |
