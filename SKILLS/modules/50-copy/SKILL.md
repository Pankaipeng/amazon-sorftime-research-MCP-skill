# 50 · 文案生成

> 导图对应：输出层「Listing 文案」。上游是 `40-selling-point` 的定稿卖点，下游是 `60-image-brief` 的图位文案。

一句话：**把"能写什么"（事实卡）和"该写谁"（定稿卖点）变成"怎么写"（文案），并保证每个词都可回查、每条格式都可上架。**

50 用独立规则选点和排序。40 提供 FAB、证据和参考 M 分。成稿体检由 `amazon-listing-doctor` 执行。

## 输入

| 输入 | 文件 | 用途 | 缺了怎么办 |
|---|---|---|---|
| 事实卡 | `调研/{cat}/00-事实卡.json` | 数值、材质、适用面、禁写项的唯一来源 | **必需**，缺了整个模块不能跑 |
| 定稿卖点 | `调研/{cat}/00-选定卖点.json` | 5 条卖点、顺序、每条的 claim 与词位 | **必需** |
| FAB 卖点卡 | `调研/{cat}/selling-point/SP-10-FAB卖点卡.csv` | 核对使用状态与可用主张 | 配置了 `inputs.fab_cards` 时必需 |
| 词库 | `调研/{cat}/keyword_library.csv` | 覆盖判定的词池、`prio`、`W`、`R`、`root` | **必需** |
| 卖点库 v2 | `调研/{cat}/selling-point/SP-01-卖点库_v2.csv` | 查参考 M 分、支撑词、覆盖度和等级 | 配置了 `inputs.selling_point_library` 时必需 |
| 埋词 SOP | 本模块 `references/02-埋词原则.md` | 冲突裁决与阈值 | 已内置，不需要外部文件 |

三样必需输入都从文件读，不靠上下文记忆。每一步落文件，下一步读文件。

在 `copy.json` 的 `bullet_sp_ids` 数组按五点顺序逐条记录定稿卖点 ID。自检核对 ID、事实核对状态和五点计划。

启用 FAB 卡后，选定卖点须为「可用」，`claim` 须填写卡片原有的「可用措辞」，每条五点须记录 ID。扩写时保留事实、适用条件和验证边界。当前海绵架配置会拦截未经核准的强吸附、抗滑及长期稳固表达，并允许在安装说明中描述事实卡已确认的吸盘数量。人工逐条核对扩写后的含义。

配置卖点库 v2 后，自检按 SP ID 核对参考 M 分。Excel「07_卖点依据」展示对应分数和来源。

### 50 的选点与位置

先从可用 FAB 主张中筛选，并剔除同一个买家利益的重复候选。对剩余候选用 0–4 分评估购买决策价值、新增信息量和差异化，分别加权 45%、35%、20%。选点分为 `(45×购买决策价值 + 35×新增信息量 + 20×差异化) / 4`，权重以 `copy_config.yaml` 的 `bullet_selection` 为准。

购买决策价值从无影响到直接决定能否购买或使用。新增信息量对照标题、Item Highlights 和已选的点，从无新增到补足关键规格或适用条件。差异化从无可比证据到有明确的本品事实与竞品对照。1 分代表增量较小，2 分代表有用，3 分代表对主要购买问题有明显帮助。每选一条，按更新后的信息覆盖重新评估余下候选。新增信息量为 0 的候选合并或换点。

默认依次安排核心差异化、核心功能、使用体验、使用场景、规格与购买决策。会决定能否使用的规格、兼容性或安装条件可以前移。缺实测规格时选有依据的材质或其他独立信息。每条以产品事实、用途及必要条件写成可独立读懂的表达。

在 `copy.json` 里按最终顺序写 `bullet_plan`。每项含 `sp_id`、`role`、`buyer_question`、`new_information`、`placement_reason`，以及整数评分 `purchase_value`、`new_information_value`、`differentiation`。实际职责可以与默认位置不同，理由写入 `placement_reason`。Excel「09_选点与排序」展示评分和取舍。

在 `copy.json` 的 `bullet_translations` 数组按五点顺序填写最终英文稿的中文对照。中文应保留英文的产品事实、适用条件及措辞力度。默认配置会校验条数和中文内容，「07_卖点依据」并列展示最终英文与中文。

### 五点语义去重

由生成五点的 AI 执行。选点时先用 FAB 提炼每条的主要买家利益，成稿后对照最终英文五点，再逐对比较一次。五条共十对。判断时问：删去其中一条，买家会少知道一个独立利益，还是只少知道同一利益的结构细节、同义说法或另一个使用场景？后一种情况合并到主卖点，用另一条已核实的独立卖点补位，再按五点职责重排。如果凑不齐五个独立利益，列出缺口并停止交付。

例如 SP11「洗刷工具一起收纳」和 SP13「海绵、刷具分区」合成一条，分区作为结构依据。SP17「底部开孔沥水」解决湿工具积水问题，可以单列。

在 `copy.json` 中写入 `bullet_semantic_review`。其中 `sp_ids` 和 `bullets` 为最终 ID 和英文原文快照，`buyer_benefits` 按五点顺序记录主要利益，`pairs` 每项含 `sp_ids`（按成稿顺序的两个 ID）、`verdict` 和 `reason`。已确认双方各有独立利益时填 `distinct`，并写明差异。还有疑似重复时先修改稿件再重审。脚本核验记录是否完整、是否对应当前稿及是否存在未解决项，语义判断由执行 Skill 的 AI 完成。Excel「08_五点语义去重」保留逐对判断依据。

后台 Search Terms 优先从 10 的词库提取前台未覆盖、与事实卡一致的增量词。可用本品事实支持的品类通用同义词补充，并在 CP-01 写明出处。后台和前台去重，默认交付目标是 125–249 个 UTF-8 字节。CP-03 对 P2 标出后台补足的词，P0/P1 仍按前台验收。


## 执行顺序

### 标题与亮点的词位和字符预算

标题先保留品牌、核心品类词和能帮助买家识别或比较的已核实属性。亮点面向移动端扫读，默认依次安排核心差异化或痛点回应、核心特征、功能利益、使用场景或适用条件。按产品证据合并或省略相近内容。亮点写逗号分隔的短语，每段提供一项独立信息。五点展开事实、用途和适用条件。

在写稿前用 10 的词库和 40 的 FAB 确定必含信息及候选表达。优先试排高相关 P0，再看能表达新增利益、属性或场景的 P1。用词库的来源、相关度与 W 判断需求，估算权重与实测搜索量分别标记。标题因字数放不下的高权重词，逐条试放亮点。词义要与本品事实匹配，标题和亮点合读时应增加信息。材质词需有可核实搜索需求，或能回答重要购买问题。

出稿前同时复核标题和亮点的剩余预算，默认美国站上限分别为 75 和 125 字符，含空格。先试压缩低价值表述或调整词序，再补有意义的高权重词和已核实的购买信息。标题与亮点按信息去重。为表达新增事实必须重复的核心词可以保留。高权重候选均已覆盖或补入会导致重复、含糊或越权时，保留空余。

在 `CP-01-词位分配.csv` 记录最终词位和词库来源，在文案报告记录目标和实用字符数、试排的高权重候选、去向或舍弃理由。最后对照 `CP-03-覆盖清单.csv` 核对实际命中。格式自检通过后仍须完成这次预算复核。

### 生成与验收步骤

1. **读三个输入**。事实卡缺失或 `_unfilled_required` 非空时，先回到 `00-事实卡输入卡.html` 补，不要凭猜写。
2. **定词位**。按 `01-词位规则.md` 把词分到标题/亮点/五点各点，落 `copy/CP-01-词位分配.csv`。列固定为：

   | 列 | 含义 |
   |---|---|
   | `序号` | 按字段顺序编号（title → highlights → bullets[0..4] → search_terms；若写描述则插在 search_terms 之前） |
   | `字段` | 目标字段，与 `copy.json` 同名 |
   | `落位词` | **要落在该字段的那个具体词形**，不是关键词原文（例：关键词 `kitchen sink organizer`，落位词写 `organizer`） |
   | `prio` | 该落位词承载的最高优先级 |
   | `命中形式` | `EXACT` 整短语原样出现 / `STEM` 词序或单复数变化后命中 |
   | `本行新增覆盖` | 加上这个词后新覆盖的关键词个数（增量口径，累计应等于覆盖预演总数） |
   | `说明` | 为什么放这里 |
   | `新增覆盖的搜索词（示例）` | 最多 3 个，供人工抽查 |

   **只列需要设计的落位词**。被包含关系白拿的词（`sponge holder` 之于 `sponge holder for kitchen sink`）由脚本在 `CP-03-覆盖清单.csv` 里体现，不进词位表，否则表会膨胀到几十行且全是 0 贡献行。

   **定完词位后，按 `06-决断规则.md` 逐条过三个判定**（词要不要写、零覆盖条目留不留、亮点能不能重复标题），**不要回来问用户**。三条判定的阈值在 `copy_config.yaml` 的 `decisions` 段。只有事实缺失、商业取舍、品牌调性三类才问人。交付时附「自动决断清单」（06 第六节），让用户事后抽查。

3. **写标题 + 亮点**。标题按**四段**组：品牌 + 核心品类词 +（同义变体，新增 W ≥ 5,000 才加）+ 差异属性；超 75 先做词干压缩，再按序砍（先规格后场景）。亮点先平铺差异化、利益、安装、材料、场景和边界，再按 [40 的评论卖点拆解](../40-selling-point/SKILL.md#把评论拆成可用卖点) 与 FAB 可用措辞排序，最后补词。首段优先回答影响购买且有本品事实能回应的问题，以具体短语表达。买家影响及本品证据接近时，再比较有证据的差异化。缺竞品图时，D 仅作文字覆盖参考。其余段优先补标题未交代的用途、适用条件或已确认的结构。
4. **写五点**。执行「50 的选点与位置」，每点以冒号后的主张、分号分隔的短语和场景或证据组成，句末不加标点。防退信息放在最相关的一点。
5. **写 ST**。词库 −（标题 + 亮点 + 五点），只留 `R ≥ 0.6`，小写空格分隔，≤250 字节。
6. **描述（可选，默认不写）**。项目大纲输出层只定义四个字段；且 30 个竞品的 `description` 字段全部为 null，本项目没有描述语料可对标。**用户明确要求时才写**，2000 字符、零 HTML、纯文本空行分段（7 段是常见结构，不是硬要求）。写了要在口径声明里标明"大纲外字段、无竞品样本"。
7. **跑自检**：`python skills/scripts/check_copy.py --category {cat}`。退出码非 0 不许交。全绿之后还要过 `08-自检清单.md` §六的 6 条人工项——脚本查不了语义重复，全绿不等于能交。
8. **补覆盖理由**。`CP-03-覆盖清单.csv` 里 P1 未覆盖且无理由的，回填 `coverage_reasons` 后重跑。
9. **出报告与交接**。`文案报告.md` 按 `_common/输出规范.md` 的骨架写（口径声明 / 主结论 3 条以内 / 明细表带 confidence / 缺失与不确定），再写 `60-image-brief交接单.md` 给下游。
10. **跑第三方体检**：`python skills/scripts/score_copy.py --category {cat}`。它把 `copy.json` 归一化成 `CP-07a-评分输入.json`，调 `SKILLS/skills/amazon-listing-doctor/`（MIT，见该目录 `SOURCE.md`），输出 `CP-07-评分明细.csv`。标题或亮点未用满时，按字符预算规则复核高权重候选和新增信息，并在文案报告记录取舍。工具缺失时评分表标「未执行」。
11. **交付**。顺序固定：`check_copy.py`（写 08 / CP-03 / CP-04）→ `score_copy.py`（写 CP-07 三件）→ `build_copy.py --category {cat} --sku {sku}`（写 CP-02 / 粘贴稿 / CP-05 / CP-06 / 文案.xlsx / _summary.json）。**这三份脚本产物不许手写**，字符数一改就漂。

首次跑通前还要做一件事：`python skills/scripts/check_facts.py` 的自检必须过——**例外是 C1 里由 `dims.outer_in` 三项引起的骨架缺失**，那是 2026-11-18 用户裁定「卖点不需要三维」后的已知长期 FAIL，不是缺陷，不用为了变绿去补包装值。除此之外的任何 FAIL（尤其 C2-C5 的事实冲突）都要先解决再写文案，否则事实层没立住，写了也要返工。

### 命名与格式

`CP-` 前缀与 `10-keyword` 的 `00~10`、`40-selling-point` 的 `SP-` 区分，三套编号不许重叠。`08-` 固定是自检，对齐 `08-交付自检.txt` / `08-卖点库自检.txt`。

| 格式 | 文件 | 给谁用 | 为什么是它 |
|---|---|---|---|
| `json` | `copy.json` | 脚本 / 下一版迭代 | **唯一真值**。其余全部由它派生，改文案只改这里 |
| `csv` | `CP-01`~`CP-06` | 跨 SKU 汇总 / 复核 | 一行一记录，追加即复用；Excel 里 `=LEN()` 能复算字符数 |
| `txt`（纯文案） | `上架稿-可直接粘贴.txt` | 粘贴到后台 | 零标注、零前缀，一行一个字段，整行选中即可。**唯一必须用 txt 的场景** |
| `md` | `文案报告.md` / `09` / `90` | 人读 | 表格能渲染对齐，git 能逐行 diff；代码块里的文案不会被换行拆断 |
| `xlsx` | `文案.xlsx` | 人看 / 转交 | 与 `卖点库.xlsx` 同一套版式：深蓝表头、冻结首行、自动筛选 |

为什么说明稿不用 txt（2026-11-17 实测）：txt 靠空格对齐，中英混排下 5 张 ASCII 框线表**全部错位 1-3 列**；且 txt 没有代码块语义，文案与编号只能待在同一行，整行复制会把 `B1  ` 带进后台。这两条都是 md 能解、txt 解不了的。

### 派生文件一律由脚本生成

```
python skills/scripts/check_copy.py --category {cat}    # 写 08 / CP-03 / CP-04
python skills/scripts/score_copy.py --category {cat}    # 写 CP-07 / CP-07a / CP-07b（调 vendor 体检工具）
python skills/scripts/build_copy.py --category {cat} --sku {sku}   # 写 CP-02 / 粘贴稿 / CP-05 / CP-06 / 文案.xlsx / _summary.json
```

**理由**：手抄会漂——本项目已经漂过两次（说明稿写「五点 167-189」，实际 153-169；`B1  ` 前缀混进文案行）。凡是从 `copy.json` 能算出来的数字，都不许手写。

硬规则：

- **顺序固定：check → score → build**。`build_copy.py` 的 `04_评分` 表读 `CP-07`，没有就是空表 + 「先跑 score_copy.py」提示，不报错
- **体检问题逐条复核**。对重复词、合规和后台词问题核对原稿。对字数利用率提示复核可用的高权重候选，将采纳或舍弃理由写进 `文案报告.md`。
- **顺序固定：先 check 再 build**。`build_copy.py` 从 `08-文案自检.txt` 读结论，不认 `copy.json` 里的手写字段。08 不存在 → 直接退出码 2 并提示先跑 check；08 里有 FAIL → 产物照写（供定位）但退出码 1，不许上架
- **自检结论只有一源**：`08-文案自检.txt`。xlsx 的 `05_自检` 表、`CP-06` 的 `check_result` 列、`_summary.json` 的 `check` 字段全部从它解析出来，不许手填
- **空白问题清单的含义写进交付物**：`CP-04` 只有表头 = 本轮 0 条违规。xlsx `00_说明` 必须有「自检结论」和「问题清单」两行，否则看表的人会误判成没执行
- 粘贴版里**文案必须独占一行、行首无编号**；`Header: 事实` 里的冒号是官方格式，编号不是
- csv 一律 `utf-8-sig`，否则 Windows Excel 打开中文乱码
- 改完文案两个脚本都要重跑，退出码都 0 才算交；`文案报告.md` 里的数字同样以脚本输出为准

## 硬规则

1. ⛔ **无事实不写数值**。承重、尺寸、材质牌号，凡事实卡没有的一律不写；`load.tested = false` 时全篇禁 `lbs` / `pound` / `kg`。
2. ⛔ **不许拿竞品宣称当本品事实**。`holds up to 11 lbs`、`TPE suction cup`、`octopus-inspired bionic` 均来自竞品 TAILI 的 `asin_detail.features`，进文案即虚假宣传。
3. ⛔ **P0 词未覆盖 = FAIL**。P1 可放弃，但必须归因到 L0/L1/L2，写不出归因不算理由。
4. ⛔ **格式服从官方，不服从语感**。五点冒号 + 分号 + 句末无标点；描述零 HTML；ST 按字节。
5. ⛔ **阈值与词表一律进 `copy_config.yaml`**，脚本不硬编码。写死在代码里的数据等于让产物和数据脱钩。
6. ⛔ **不许为覆盖率牺牲可读性**。L1 压过 L2：删词，不改句子结构。
7. ⛔ **改文案必须回查卖点库**。`soap` 那次就是只改文案没改库，下一版又写回来。
8. ⛔ **不自造评分**。评分走 `amazon-listing-doctor`，本模块只出 PASS/FAIL/WARN 三态。
