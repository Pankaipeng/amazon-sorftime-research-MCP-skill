# 输入层：三类输入

下游所有模块都从这里取料。**输入不齐，后面的模块就停在原地，不要用猜的补。**

---

## 1. 竞品 ASIN 组（必填）

不是随便给几个 ASIN，而是**分层抽样**——四类各司其职，缺哪类就在报告里标出来。

| 类别 | 数量 | 作用 | 对权重的影响 |
|---|---|---|---|
| **头部竞品** | 1-2 | 定义行业天花板、标题和图片的"标准答案" | ×3（L0） |
| **直接竞品** | 3-5 | 同形态、同价位、同人群，是可替代对象 | ×1（L1） |
| **新品** | 1-2 | 反映近期打法变化，老链接看不到的新词常在这里 | ×2（L1.5） |
| **反查扩池** | 自动 | 从上面三类向外扩一层，补足样本量 | ×0.5（L2） |

**为什么新品要单独给权重**：老品的关键词结构是两年前定型的，新品才反映当下算法偏好。给到 L1.5 是为了不被老品的惯性带偏。

### 交付格式

```json
{
  "marketplace": "US",
  "groups": {
    "head":   ["B0XXXXXXX", "B0XXXXXXY"],
    "direct": ["B0AAAAAAA", "B0AAAAAAB", "B0AAAAAAC"],
    "new":    ["B0NNNNNNN"]
  }
}
```

层级固定：`head` → L0（×3）、`direct` → L1（×1）、`new` → L1.5（×2）、扩池 → L2（×0.5）。

### 反查扩池（两步，缺一不可）

**第一步：从用户给的 ASIN 向外扩一跳**

```python
for asin in head + direct + new:
    mcp__ss_mcp__asin_competitor({"marketplace":"US","asin":asin,"size":20})
```

**第二步：按类目销量补池（这步不能省）**

```python
mcp__ss_mcp__product_research({
  "request": {"marketplace":"US", "nodeIdPath":"<类目节点>",
              "nodeIdPathEqual": true, "minUnits": 300,
              "order":{"field":"total_units","desc":true}, "size":30}
})
```

取销量 Top 10，逐个核对是否已在池里。

> **实测教训（2026-11-13）**：只做第一步，漏掉了类目第一 Cisily（月销 53,444、类目 BSR 第 1），直接导致「刷子位」被误判为差异化卖点。`asin_competitor` 只按相似度扩，不保证覆盖头部。

扩出来的按规则过滤：同站点、类目路径前 3 段一致、月销 ≥ 100、排除同品牌变体。

**池子目标 8-15 个**。少于 5 个 → 词频不可信，报告里必须写"样本不足"。

## 2. 本品事实卡（必填）

没有这张卡，后面所有"差异化"都是空话。

| 字段 | 必填 | 说明 | 用在哪 |
|---|---|---|---|
| 产品定位 | ✅ | 一句话：卖给谁、解决什么、凭什么 | 相关性 R1 判定 |
| 材质 / 工艺 | ✅ | 具体到材料名称，不要"优质材料" | 差异化强度 D |
| 产品参数 | ✅ | 尺寸、数量、重量、承重、颜色等可验证项 | 标题规格槽位 |
| 差异点 | ✅ | 竞品没有或做得差的，逐条列 | Highlights、五点 |
| 使用边界 | 建议 | 不能用在什么场景 | 限制条件、退货预防 |

**差异点必须是可验证的事实**。"更耐用"不算，"承重 30 lbs、竞品普遍 15 lbs"才算。

而且**差异点必须对过完整竞品池**。实测踩过坑：一个卖点自认为竞品没有，补完池发现类目第一主打的就是它。

```json
{
  "positioning": "租房人群的免打孔玄关收纳",
  "material": ["solid rubberwood", "steel hooks"],
  "specs": {"hook_count": 5, "load_lbs": 30, "width_in": 16.5},
  "differentiators": [
    {"point": "solid wood 而非 MDF", "evidence": "wood grain photo + supplier spec"},
    {"point": "承重 30 lbs", "evidence": "lab test report 2026-09"},
    {"point": "免打孔安装", "evidence": "adhesive mount included"}
  ],
  "limits": ["不适合潮湿环境", "单钩承重上限 6 lbs"]
}
```

## 3. 后台数据（可选，但**强烈建议**）

### 为什么单列一节

卖家精灵 MCP 里有的是**公开市场数据**：别人的月销、搜索量、评论。
它**没有**你店铺自己的后台数据，也没有官方的搜索转化率。

这些数据只能从**卖家后台导出**，然后由你**上传附件**给我。
流程上它是可选的，但对准确性影响最大：**它是唯一能和公开数据做交叉校验的一手数据。**

### 需要传什么

| 数据 | 后台路径 | 关键列 | 用途 | 优先级 |
|---|---|---|---|---|
| 商机探测器 · Niche 搜索词 | 品牌分析 → 商机探测器 → 细分市场 → 搜索词 | 搜索词、360 天搜索量、90/180 天增长、点击份额、**搜索转化率** | 转化率与趋势；新品唯一能拿到的转化类数据 | ★★★ 最高（新品） |
| ABA · 热门搜索词 | 品牌分析 → 热门搜索词 | 搜索频率排名、点击第 1-3 品牌/ASIN、点击份额 | 谁在吃这个词 | ★★ |
| 广告搜索词报告 | 广告 → 报表 → 搜索词报告 | 投放词、客户搜索词、曝光、点击、花费、**订单数**、销售额 | 真实转化词、否词依据 | ★★★ 最高（在售品） |
| 业务报告 | 数据报告 → 业务报告 → 子商品详情 | 会话数、会话转化率、已订购商品数 | 校验关键词热度与转化率 | ★★ |
| 退货报告 | 数据报告 → 退货报告 | ASIN、退货原因、数量 | 痛点真值，喂给 `30-insight` | ★★ |
| 库存/成本表 | 你自己维护 | 采购成本、头程、FBA 费 | 算毛利、算 PPC 能不能打 | ★ |

**导出后原样上传就行**（csv / xlsx 都可以），不用先整理。我会自己认列名。

**新品没有订单数据也能传前两份**——商机探测器和 ABA 不需要你出过单。

### 广告搜索词报告：五路之外最值钱的一路

它是**唯一带自家真实转化的数据**。搜索量再大，不如一个真出过单的搜索词。

用法有两条：

1. **正向**：`订单数 > 0` 的搜索词 → 直接进 P0/P1，权重高于任何估算词
2. **反向**：曝光高、点击有、`订单数 = 0` 的搜索词 → 否定清单的头号候选

### 怎么标

上传的数据在报告里一律标 `sources = E`，和 A/B/C/D **分开列**，不能混着算：

- 搜索量口径不同（后台是曝光/点击/360 天，卖家精灵是月搜索量），**不能相加**
- E 类数据用于「验证」「补转化率」「补趋势」，不参与 W 的绝对值计算

字段含义与对账方法见 `10-keyword/methods/06-后台数据校准.md`。

### 没传怎么办

不阻塞。但在报告的口径声明里必须写清：

```markdown
- 后台数据：未提供
- 影响：转化类结论无法验证，P0/P1 排序仅基于估算搜索量
- 建议：补一份商机探测器搜索词表 + ABA 热门搜索词，可把 P0 判定准确率显著提高
```

**不要用估算数据假装成转化数据。** 这是这份技能里最不能犯的错。
