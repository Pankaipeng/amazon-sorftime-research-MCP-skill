# 输入层：三类输入

下游所有模块都从这里取料。**输入不齐，后面的模块就停在原地，不要用猜的补。**

---

## 1. 竞品 ASIN 组（必填）

不是随便给几个 ASIN，而是**分层抽样**——四类各司其职，缺哪类就在报告里标出来。

| 类别 | 数量 | 作用 | 对权重的影响 |
|---|---|---|---|
| **头部竞品** | 1-2 | 定义行业天花板、标题和图片的"标准答案" | ×3（L0） |
| **直接竞品** | 3-5 | 同形态、同价位、同人群，是可替代对象 | ×1（L1） |
| **新品** | 1-2 | 反映近期打法变化，老链接看不到的新词常在这里 | ×2（L1.5） |
| **反查扩池** | 自动 | 从上面三类向外扩一层，补足样本量 | ×0.5（L2） |

**为什么新品要单独给权重**：老品的关键词结构是两年前定型的，新品才反映当下算法偏好。给到 L1.5 是为了不被老品的惯性带偏。

### 交付格式

```json
{
  "marketplace": "US",
  "groups": {
    "head":   ["B0XXXXXXX", "B0XXXXXXY"],
    "direct": ["B0AAAAAAA", "B0AAAAAAB", "B0AAAAAAC"],
    "new":    ["B0NNNNNNN"]
  }
}
```

层级固定：`head` → L0（×3）、`direct` → L1（×1）、`new` → L1.5（×2）、扩池 → L2（×0.5）。

### 反查扩池（三步，缺一不可）

**第一步：从用户给的 ASIN 向外扩一跳**

```python
for asin in head + direct + new:
    mcp__ss_mcp__asin_competitor({"marketplace":"US","asin":asin,"size":20})
```

**第二步：按类目销量补池（这步不能省）**

```python
mcp__ss_mcp__product_research({
  "request": {"marketplace":"US", "nodeIdPath":"<类目节点>",
              "nodeIdPathEqual": true, "minUnits": 300,
              "variation": "Y",                       # ← 必填，排除变体
              "order":{"field":"total_units","desc":true}, "size":100}
})
```

> **实测教训（2026-11-13）**：只做第一步，漏掉了类目第一 头部品牌（月销 53,444、类目 BSR 第 1），直接导致「刷子位」被误判为差异化卖点。`asin_competitor` 只按相似度扩，不保证覆盖头部。
>
> **`variation: "Y"` 同样不能省**：不带这个参数时，头部品牌 的 30 个变体按销量降序把 Top 30 全占了，"扩了 30 个"实际只等效 1 个新竞品。上一版词频因此完全失真。

**第三步：按形态过滤，台面竞品一律不入池**

同一条类目节点里混着两种形态，必须分开：

| 形态 | 标题特征词 | 处置 |
|---|---|---|
| **壁挂 / 吸盘 / 龙头挂载** | suction / adhesive / in sink / inside sink / wall / hanging / faucet / mount | 入池 |
| **台面 / 托盘款** | countertop / tray / freestanding / free standing / extendable / tabletop | **排除，单独存一份备查** |
| 两者都有（如"台面或壁挂双用"） | — | 按本品形态归边，记 `mount` 字段 |

为什么要排除：台面款的标题大量写 `self-drain tray` / `countertop`，混进来会把 `tray` 抬成"行业通用词"；它们的卖点结构（大容量、可拆托盘）和壁挂件完全不同，混着算出来的差异化是假的。

**同时剔跨类目噪声**：同一个 nodeIdPath 下会混进完全无关的商品（实测 100 条里有 13 个是牛皮纸袋架、吸管架、香蕉钩）。判据只有一条——标题里有没有本品品类的核心名词，没有就丢。

### 扩池后的四条过滤规则

1. **同站点、类目路径前 3 段一致**
2. **月销 ≥ 100**（null 不参与过滤，标 `DATA_MISSING` 保留）
3. **`variation: "Y"` + 品牌去重**，同品牌最多留 2 个代表 ASIN
4. **形态一致**（见上表），台面款不入池

**池子目标 20-40 个，且品牌数 ≥ 15。** 少于 15 个 ASIN 时，词频只能看"词存不存在"，不能判覆盖率，报告里必须写"样本不足"。

> **实测（2026-11-13 海绵架）**：100 个候选 → 32 个带壁挂关键词 → 去掉 13 个跨类目噪声 → 19 个有效壁挂 → 加用户 6 个 + 补拉 7 个旧款 = **30 个 ASIN / 22 品牌**。同一份 `smiley face` 卖点，9 个样本时判成"独有"，30 个样本时发现 4 家在写。

## 2. 本品事实卡（必填）

没有这张卡，后面所有"差异化"都是空话。

| 字段 | 必填 | 说明 | 用在哪 |
|---|---|---|---|
| 产品定位 | ✅ | 一句话：卖给谁、解决什么、凭什么 | 相关性 R1 判定 |
| 材质 / 工艺 | ✅ | 具体到材料名称，不要"优质材料" | 差异化强度 D |
| 产品参数 | ✅ | 尺寸、数量、重量、承重、颜色等可验证项 | 标题规格槽位 |
| 差异点 | ✅ | 竞品没有或做得差的，逐条列 | Highlights、五点 |
| 使用边界 | 建议 | 不能用在什么场景 | 限制条件、退货预防 |

**差异点必须是可验证的事实**。"更耐用"不算，"承重 30 lbs、竞品普遍 15 lbs"才算。

而且**差异点必须对过完整竞品池**。实测踩过坑：一个卖点自认为竞品没有，补完池发现类目第一主打的就是它。

```json
{
  "positioning": "租房人群的免打孔玄关收纳",
  "material": ["solid rubberwood", "steel hooks"],
  "specs": {"hook_count": 5, "load_lbs": 30, "width_in": 16.5},
  "differentiators": [
    {"point": "solid wood 而非 MDF", "evidence": "wood grain photo + supplier spec"},
    {"point": "承重 30 lbs", "evidence": "lab test report 2026-09"},
    {"point": "免打孔安装", "evidence": "adhesive mount included"}
  ],
  "limits": ["不适合潮湿环境", "单钩承重上限 6 lbs"]
}
```

## 3. 后台数据（可选，但**强烈建议**）

### 为什么单列一节

卖家精灵 MCP 里有的是**公开市场数据**：别人的月销、搜索量、评论。
它**没有**你店铺自己的后台数据，也没有官方的搜索转化率。

这些数据只能从**卖家后台导出**，然后由你**上传附件**给我。
流程上它是可选的，但对准确性影响最大：**它是唯一能和公开数据做交叉校验的一手数据。**

### 需要传什么

| 数据 | 后台路径 | 关键列 | 用途 | 优先级 |
|---|---|---|---|---|
| 商机探测器 · Niche 搜索词 | 品牌分析 → 商机探测器 → 细分市场 → 搜索词 | 搜索词、360 天搜索量、90/180 天增长、点击份额、**搜索转化率** | 转化率与趋势；新品唯一能拿到的转化类数据 | ★★★ 最高（新品） |
| ABA · 热门搜索词 | 品牌分析 → 热门搜索词 | 搜索频率排名、点击第 1-3 品牌/ASIN、点击份额 | 谁在吃这个词 | ★★ |
| 广告搜索词报告 | 广告 → 报表 → 搜索词报告 | 投放词、客户搜索词、曝光、点击、花费、**订单数**、销售额 | 真实转化词、否词依据 | ★★★ 最高（在售品） |
| 业务报告 | 数据报告 → 业务报告 → 子商品详情 | 会话数、会话转化率、已订购商品数 | 校验关键词热度与转化率 | ★★ |
| 退货报告 | 数据报告 → 退货报告 | ASIN、退货原因、数量 | 痛点真值，喂给 `30-insight` | ★★ |
| 库存/成本表 | 你自己维护 | 采购成本、头程、FBA 费 | 算毛利、算 PPC 能不能打 | ★ |

**导出后原样上传就行**（csv / xlsx 都可以），不用先整理。我会自己认列名。

**新品没有订单数据也能传前两份**——商机探测器和 ABA 不需要你出过单。

### 广告搜索词报告：五路之外最值钱的一路

保留客户搜索词、点击、归因订单、销售额、花费和归因窗口。同一站点同一窗口下，结合点击分母、成本、相关性和有无订单积累来判断是否追加验证或调价。点击样本不足时保留观察，业务转化率按会话口径单列。

SEO 仍按 `10-keyword` 的现行词库规则排序。广告归因订单和转化信号写入验证记录。确认要改优先级或否词时，补充判断依据与复核人。

### 怎么标

按来源分别保留原始报表名称和观察窗口。`merge.py` 使用 `N` 表示商机探测器，使用 `E` 表示 ABA 热门搜索词。广告、业务、退货和成本导出各自保留来源名与指标定义。360 天搜索量、周搜索量、月度搜索量估算、广告曝光和详情页会话各自采用对应的统计口径。

字段含义与对账方法见 `10-keyword/methods/06-后台数据校准.md`。

### 没传怎么办

不阻塞。但在报告的口径声明里必须写清：

```markdown
- 后台数据：未提供
- 影响：转化类结论无法验证，P0/P1 排序仅基于估算搜索量
- 建议：补一份商机探测器搜索词表 + ABA 热门搜索词，可把 P0 判定准确率显著提高
```

**不要用估算数据假装成转化数据。** 这是这份技能里最不能犯的错。


## 4. 一审调研资料回流（可选）

一审材料进入项目输入目录，供当前模块复核。每条记录附来源类型、文档内表或图定位、站点、样本定义、统计起止和采集日期。比率附分子、分母、去重单位及是否多标签。缺失字段标 `DATA_MISSING`，截图读数标「待与原表核对」。

| 材料 | 回流字段 | 使用位置 |
| --- | --- | --- |
| 榜单、子类与竞品底表 | 类目节点、入池及排除原因、父子 ASIN、形态、上架日期、材质、安装、尺寸及其对象、成交价或页面快照、币种、销量及销量来源 | 20 复核可比性、量价带、形态与新品队列。标注母池规模与实际纳入样本数 |
| 评分和量价汇总 | 评分数、星级、价格档上界规则、ASIN 数、单位销量、销售额计算口径 | 20 分别展示 ASIN 等权、评分数加权、样本销量和销售额；每个百分比注明分母 |
| 一审关键词、ABA、商机探测器 | 原关键词、站点、来源、周起止、搜索、点击、购买及两类转化率 | 10 对方向与相关性作交叉核验；有效期和周次确认后才参与时间比较 |
| 评论图、VOC、好差评和 Q&A | 评论键、ASIN、星级、日期、来源、场景、收纳物、动机、期望、问题、证据定位 | 30 汇总时按各来源分母展示；图片仅支持可观察场景，商机探测器聚合和评论级标注分别留存 |
| 退货数据 | 站点、范围、周期、退货数和对应销量、退货原因、数据来源 | 30 区分市场细分退货率、相邻商品和本品。遇到标题与表头冲突，按实际字段记录并标待核 |
| 原型、会议决议与产品验证 | 版本、候选方案、决议、责任人、期限、验证条件、原始记录、批准可用主张 | 00 更新本品事实与边界，40 据此核验主张，50 和 60 仅消费已确认事实 |

调研过程中保留原始假设、验证结果和变更原因。交付后按 Listing 版本、站点、时间窗记录评分、退货、转化及促销、库存等干扰项。用新观测修订下一轮输入。原始数据、公司内部链接与业务标识保存在授权的项目目录。
